Principles

Principles behind every design choice, and what Corset does not do.

  • When unsure, do what Rust and Clippy do.
  • Every decision is revisable. Evidence from corpus runs and users outranks earlier reasoning; see design reviews in plan.md.
  • Compute each expensive step once per run. Share output with every rule.
  • Footguns are source of truth. Rules group footguns by analysis they read. User-facing group is metadata only.
  • Give each finding confidence: definite (problem exists) or possible (compiler cannot resolve doubt either). One setting filters them. Corset blind spots go to coverage line only (findings.md).
  • Map every finding back to source bytes. Fixers edit lossless syntax tree.
  • Rule is small query over shared facts. Analysis stages compute every fact once per run; rule only reads them.
  • Each fact has one producer. Rule never guesses later-stage fact (type, mutability, effect, ADT variant) from syntax; it waits for that stage.
  • Rule belongs to last stage its findings need. One rule never mixes syntax footguns with footguns of later stages.
  • Fixer may read later stages when they ran. Otherwise its fix is manual.
  • Every finding explains itself: cause spans, one-line reason, concrete fix. Rust compiler errors set bar.
  • Cache findings on disk. Unchanged code is never analyzed twice, across restarts too.
  • Keep linter process warm. Load target package once. Infer each package method once; every typed rule shares result.
  • Read typed IR from native compiler at lint time. Other linters (JET, fatou, LintApp.jl, ReLint.jl) serve only as test references and code sources.

Non-goals

  • Formatting: Runic or JuliaFormatter own it.
  • Relying on package tests or precompile workloads. Facts come from source, type annotations, loaded module and inference. Package without tests or workloads gets full analysis. Code that ran before Corset changes speed only, never findings.
  • Findings in dependency code, Base included. Analysis reads dependency code freely (callee summaries, inference); only findings stay inside package. Code that package macros write counts as package code; code that other packages' macros write does not.
  • Julia versions older than latest release.
  • Security sandbox around package code. Corset loads code its user chose to lint.
  • Version 1: language server; race and ownership analysis. Thread pattern rules F68–F70 stay.

Pipeline

Analysis stages Corset computes, in pipeline order. Each stage computes facts once per run; rules read them.

Stages run top to bottom. Stage not built yet gives no facts; no rule reads it until it ships. Rule declares two stages: stage for findings and fix_stage for fixes, never earlier. Engine computes only stages selected rules need for either. scope runs after package: macro expansion needs evaluated imports and package macros. Scripts: scope evaluates imports only; unresolved macros go to coverage line.

syntaxSyntax patterns

One tree walk per file. Rules are Argus.jl patterns: syntax classes, pattern forms, templates for fixes. Walk indexes rules by pattern root kind and asks Argus to match candidate nodes only. Findings

How findings are graded, filtered, configured, shown and fixed.

Five groups: correctness, safety, performance, composability, readability. Correctness holds code that misbehaves now: input, path or broken contract. Safety holds code that works now but lets later mistake pass silently; its fix makes Julia catch mistake. Readability holds house style: anything that makes code hard to read. Composability holds code that must work with other types and future Julia versions.

Noise is no longer reason for group. Each finding says how sure analysis is. One setting picks what to report:

Safety test: does fix turn silent mistake into error, failed check or failed test? broad-catch fix rethrows unexpected errors; unchecked-enum fix gets exhaustiveness check.

Confidence and blind spots

confidence sets lowest confidence finding needs to be reported. definite (default) reports definite findings only; possible reports both. likely can join between them later.

Doubt test: can Julia compiler resolve doubt? Compiler sees code, types and method table when it compiles call. It never sees run-time values, foreign code or methods added later.

resolves; problem exists proves problem definite finding
cannot resolve cannot resolve finding: possible, or rule of its own
resolves cannot resolve blind spot: coverage line only
  • Finding: untyped argument reaches methods that disagree on writing it. Compiler dispatches at run time: bang-convention reports possible, and runtime-dispatch reports call.
  • Finding: public function returns union from dependency. Unknown callers decide: possible.
  • Finding: write lands below argument w past place Corset names. Doubt is only where it lands: w changes, so bang-convention keeps certainty of write.
  • Blind spot: syntax-only rule cannot see that a::Vector is 1-based, because inference stage did not run.
  • Blind spot: inference gave no code (generator threw); method has more signatures than limit; argument type has no stand-in.
  • Blind spot: no call reaches untyped method; macro did not expand; include path is computed.
  • Exemption needs proof: rule counts access Corset cannot prove exempt (balanced lock, IO or RNG write). Rare false finding takes # corset: allow.
  • Corset limits never fall below compiler limits (max_methods, union splitting). Corset resolves every call compiler resolves.
  • Rules assume Base functions keep documented contracts: == has no side effects, and comparison with NaN is false. Method that breaks contract is out of scope, as for Clippy ifs_same_cond.

Coverage line ends every run and counts blind spots by cause: analyzed 412 of 430 methods; skipped 18 (generated function: 2, unexpanded macro: 16). Rule that lacks fact at site reports nothing there.

Lint levels

Clippy model: each group and each rule has level allow, warn or deny; rule level overrides group level from any source. Command-line flags beat config; config beats preset. deny findings fail run; --deny warnings makes warnings fail too. Baseline findings never fail run.

Opt-out comments

Modeled on Rust lint attributes. # corset: allow <rule>, <rule> -- <reason>; reason is required. After code, comment covers that line. On own line, it covers next statement: function, struct, block or expression. # corset: allow-file <rule> -- <reason> before first code covers file, like Rust inner attribute #![allow].

Malformed comment, unknown rule, late allow-file, and opt-out that suppresses nothing are errors; they always fail run, like unfulfilled #[expect] under -D warnings. Opt-outs apply to findings before levels and confidence filter, so config change never orphans opt-out.

Parse errors

JuliaSyntax parse error is error finding at deny, outside rule table, as Ruff reports syntax errors. No level, opt-out or baseline hides it. Rules still run on recovered tree.

Load errors

Package that throws while loading gets load-error finding at deny, outside rule table, as parse-error. Primary span: deepest backtrace frame inside package source; package entry file when none. Message carries exception text. syntax rules still run; later stages skip, and coverage line says package did not load. Failed precompilation is load error too: Julia throws and loads nothing. Precompile error has no frame in package, so second load in anonymous module supplies frames; precompile-only failure points at entry file. Extension that throws gets load-error at its file; package rules still run, and coverage line counts extension. Extension whose trigger environment cannot load is blind spot.

Fix tiers

Each fix declares tier by risk to callers; one setting picks highest tier applied automatically. Test: would anyone's code need to change?

  • safe: proven equivalent, or fixes definite bug inside method (where-binding parentheses, untyped-empty on local array).
  • likely: changes types callers see (overspecified-type: ::Float64 → ::Real).
  • breaking: changes public API (type-disruption adds array-type parameter). Ratchet absorbs new findings.
  • manual: needs human choice (new name, sum type). Shown, never applied. Later: prompt for choice in CLI, or hand off to LLM.

Macro output

Rules read code as written, macro arguments included. Code that package macro writes gets findings: one finding at macro definition, with call-site count. Code that other packages' macros write gets none, since package cannot fix it (Clippy in_external_macro). Fixes never edit generated code. Syntax stage sees source as written; findings in expanded code come from stages after load. Syntax stage skips quoted code outside $ interpolation, and macro arguments with {} (Argus patterns), which lowering always rejects. {} check is stopgap; revisit with general check in plan later row. Code passed through macro (@inbounds, @views) maps to exact bytes. Code macro writes itself maps to line: call-site line for macro of other file (outermost debuginfo scope), nearest line inside definition for macro of same file and @generated output. Julia 1.13 lowering keeps no byte provenance; JuliaLowering on 1.14 fixes it. Location without source mapping goes to coverage line.

Conventions

  • Corset supports only latest Julia release, for running and for fixes.
  • Public API: exported or declared public. Everything else is internal.
  • test/, docs/, benchmark/ are scripts: loading them runs them.
  • Baseline lives in corset-baseline.toml at project root; corset baseline writes it. Entries match findings by rule, file, enclosing definition and normalized snippet hash. No line numbers, so edits elsewhere keep matches. Baselined findings stay hidden. Entry that matches no finding fails run until corset baseline rewrites file, like ESLint bulk suppressions.
  • corset explain and docs page per rule follow Clippy sections under plain headings: Description, Rationale, Example, Alternative, Limitations. Text lives in rule module docstring; registry test enforces sections.
  • Fixes keep surrounding style; formatting stays formatter's job (Runic, JuliaFormatter).
  • Additive replacement for literal uses oneunit(x), never one(x): one drops units (Unitful.jl).
  • Corset lints itself in CI from phase 1.
  • Renamed rule keeps old name as alias that warns, so opt-out comments survive renames (Clippy renamed-lints list).

one-letter exemptions

Allowed: type names and type parameters (T, N); i, j, k as indices. Everything else needs descriptive name.

Types

Typed analysis: stand-in types, type-disruption, lost narrowing, arguments, unions, sum types.

No tests

Corset never reads or runs package tests. Signatures come from annotations: stand-in types for generic arguments and struct parameters (from their bounds), declared type otherwise. See Arguments without stand-in.

Array stand-ins

  • Array argument takes array stand-in shaped as its annotation: stand-in kind replaces container, element and dimensions keep annotation bounds.
  • AbstractVector gives ArrayStandIn{<:Any, 1}. AbstractArray gives ArrayStandIn with open dimensions. AbstractVecOrMat gives one stand-in per member.
  • Element bound below Any that number stand-ins fit takes them, as number argument does: AbstractVector{<:Real} gives float and integer elements.
  • Number stand-in elements keep float promotion that type-disruption reads (xs .* 0.5).
  • Other element stays open (ArrayStandIn{<:AbstractString, 1}). Concrete Any element decides element-type calls: oneunit(eltype(xs)) fails, so loop body is dead.
  • DenseArray and StridedArray bounds take DenseStandIn.
  • Open stand-in is not concrete. Call reaches untyped method when each argument type is concrete once its variables take their bounds (view of open stand-in too).

Arguments without stand-in

  • Package abstract type (s::Shape): infer once per concrete subtype package defines, with stand-ins for its parameters.
  • Struct parameter takes every stand-in its bound fits, package struct stand-ins included (Outer{S <: Inner}).
  • Struct parameter no stand-in fits takes its bound. Field of type Any acts as ::Any argument: its data gives no findings.
  • Struct that bound makes empty gets no stand-in: Sized{N} with N = Any has field type Union{}.
  • Union or abstract argument takes first stand-in of each struct before second of any, so cut at signature limit reaches most structs.
  • Macro that rebuilds struct (@concrete struct) gives constructors its own file; struct ties to its form by name.
  • Function argument: stand-in function returns Any (inference barrier). Its call has unknown compiler effects, so compaction keeps it and effects sees open call. Method stable under that assumption is exempt: stable whenever f is. Problems method causes itself are reported. Code after f's result stays analyzed; values from that result give no findings. Opaque result type truncates inference frames.
  • No stand-in yet (AbstractString, AbstractDict, abstract type without package subtype) and explicit ::Any: no findings from that argument's data.
  • Unannotated method reached from analyzed caller is analyzed through caller inference: inference stage keeps explicit worklist of package frames reached from stand-in callers. Unannotated method nothing calls is skipped; annotation reports it. Expect low coverage on unannotated packages (Distances: 165 of 283 methods) until annotation fixer runs.
  • Method Corset cannot analyze is blind spot: coverage line counts it with reason.

type-disruption engine

Principle: values from outside inputs are weak. Literals, constants and globals must not change result type. Inputs combine by normal promotion. Same rule as NumPy 2 for Python scalars.

Each is ordinary well-behaved type, and promotes like narrowest real type of its kind: float stand-in absorbs Int and loses to Float64, like Float32; integer stand-in loses to Int, like Int32.     • Weak value: number literal, constant, call of weak values only (sqrt(2), 2π, (1.0, 2.0)), variable assigned one (s = 0), or Base number type name as callee, convert target or broadcast function.

Input absorbs weak value: with input swapped to Float64, conversion changes nothing. Pair, tuple and struct with own parameter per field fail this test (x => 0.5), and so does default value (get(table, x, 0.5)). Lazy broadcast compares array it materializes to. Builtins (getfield(t, 2)) change no result type.

Converted value meets more input (x * 2.0 + 1.0), so rounds repeat until no new meeting. Then each weak value stays unconverted alone: changed returned or stored type is escape; changed number intermediate only is widening. Escape analysis tracks heap objects only, so it cannot decide this.

lost-narrowing scan

  • Lowering stores value of a && b in variable when guard || exit or if !(…) branches on it. Inference narrows variable on branch of type test only, so narrowing ends inside chain.
  • Lowering branches directly on || chain, ternary condition and if a && b, so narrowing stays there. Condition stored in variable (ok = a || b) loses it.
  • Scan (inference stage, Narrowing): follow control flow of typed code as inference does. Also carry what each variable that holds condition proves when true and when false.
  • Type tests: x isa T with constant T, x === nothing, x !== nothing, isnothing(x), and their negation.
  • Loss: read where scan proves narrower type than inference gives at start of block. Inference keeps variable types per block, so check needs no second inference.
  • Exception handler proves nothing: it can run after any statement of try body.
  • Report loss when test maps to term of && or || chain; other losses give no finding. One finding per test; first read is cause span.
  • Fix: one guard per term, safe. Guard must be own statement with unused value, exit must leave block (return, continue, break, throw, error, rethrow), and no comment may sit inside. Else manual.

Annotation transition

Helps unannotated package reach full annotations. annotation fixer guesses types; message shows evidence for each guess.

  • Evidence, strongest first: argument types at package's own call sites, inferred through annotated callers; default values; struct fields argument flows into; operations body applies (arithmetic gives Number, indexing and length give AbstractArray).
  • Widen evidence to family: numbers to Real (Integer when all integer), arrays to AbstractVector{<:Real}, struct to nearest abstract supertype; union of at most three families. Keep guess only when it holds every observed type. Scheme comes from legacy typed fixer.
  • Result annotation: infer with chosen argument types; map stand-ins back to type parameters. Tier likely.
  • Argument guess with call-site evidence: tier breaking, since narrower annotation can reject callers. Body-use evidence only: tier manual.
  • After fix, Corset checks again: internal call that no longer matches shows as never-succeeds.
  • application and script presets apply breaking fixes automatically, so they transition in one run. library needs --tier breaking.
  • Built (Guesses.annotation_guesses): call-site evidence comes from every inferred caller, concrete or stand-in, with result type at call. Typed method adds results of its own stand-in inference. Literal default value adds its type.
  • Result guess is likely only when own inference covers every argument type. Untyped keyword, signatures over limit, crash or missing code make it breaking: results then miss some argument types.
  • annotation stays syntax stage with fix_stage = inference: run computes inference facts when rule is on, so fix never depends on other rules. Without package, fix stays manual.
  • Partial guess (some causes) applies; next run guesses rest. UI test applies fixes until only manual fixes remain, at most three rounds.
  • Not built: struct field flow and body-use evidence (manual tier). Keyword arguments get no guess.
  • Revisit after phase 4: evidence ranking, widening and tiers are first guesses. Measure on corpus how many guesses survive review; adjust. Candidate extra sources: docstring signatures, opt-in run-time type trace, LLM handoff for manual guesses.

Hard-coded arrays

type-disruption reports hard-coded Array construction in method with input array (HardArrays scan, inference stage).

  • Construction: zeros, ones, fill, similar(Vector{T}, dims), and Array type called with undef (Vector{T}(undef, n)).
  • Template: argument of stand-in array type. Prefer argument that dimensions read (zeros(length(ys)) takes ys); else first.
  • Scan: put StandIns.Templated callee in place of constructor in copy of lowered code, so result takes template's stand-in array type. Then leave each construction unconverted alone, as Widening does.
  • Escape (returned, or stored where store does not convert): definite. Meeting (call takes construction and array from input, buffer .= xs): possible, since mixing fails only for some array types (GPU).
  • Callee that takes Array only drops construction, as weak number that makes call throw.
  • No input array: no finding. Method has no caller's array type to keep, and adding array type parameter changes its API.

Units

  • Effects reads units of inference stage: method and stand-in signature, plus signatures package calls reach. Effects adds no roots.

  • Verdict of method: worst over its units.

  • Unit that always throws on its signature gives no verdict. Coverage reason: always throws on stand-ins.

IR

  • inference stage hands typed code of units it inferred this run to effects. Stored unit needs no typed code: its entry keeps effects record (see Solve and cache).

Origins and points-to

  • Origin: abstract object. Kinds: caller place (parameter or global path), allocation statement, unknown.
  • Constant object in code counts as unknown. Fresh objects of callee merge into one allocation at call statement.
  • unknown: object open call can return that no operand names, global included. Write to it is possible global write.
  • Path: field name or element. Path follows declared field types.
  • Path collapses to deep at step into concrete type it already passed (recursive type), at third abstract step in a row, or past 8 steps.
  • Place says where access lands; certainty says whether it happens. deep w is coarse place: write below it still changes w.
  • Field name comes from concrete type, array stand-in family or Array family. Other struct family (Object{K, V} where …) gives field position.
  • Memory backing belongs to its owner: field of type GenericMemory or GenericMemoryRef adds no step. Write to Vector elements writes Vector.
  • Ptr value holds origins of object it points into, so foreign call through pointer writes that object.
  • Constant null pointer global (C_NULL) points into no object.
  • Points-to: inclusion-based, field-sensitive, over SSA values and origin contents. Heap is flow-insensitive; SSA values keep flow.
  • Unification is rejected: it merges unrelated objects at each unknown call.
  • Write: statement that stores into origin content, or callee summary write mapped through call operands.
  • Each origin in points-to set carries doubt: none, code or blind. Join keeps least doubt per origin.
  • Open call on chain gives code. Call result merged from several fresh objects gives blind: they can hold different caller objects.
  • Collapsed path and load of non-constant slot add no doubt: object they reach lies below same root.
  • Access below deep w takes kind of written object type at access, of callee access, or of w type.
  • Exempt kind needs proof, as balanced lock use does. Raw write into IO memory below deep w is memory write: # corset: allow covers it.
  • Access takes most doubt of effect and chain. None gives definite; code gives possible.
  • blind gives blind access with cause alias: blind spot, counted on coverage line only.
  • Summary per parameter and global: read and write of top object, each path, and deep. Each has certainty and cause span.
  • Access says whether it covers every place below too. Open call covers whole object graph below each operand.
  • Access below fresh object covers caller objects in its slots: open call on (x,) writes below x.
  • Caller maps callee deep place: caller place below argument keeps access certainty. Caller object inside fresh argument gives blind: callee may leave it unchanged.
  • Summary also gives result origins as parameter and global paths: result aliases. Fresh result keeps its fields: view(A, 1:2) result holds A.
  • Summary gives stores callee makes between caller objects: push!(v, x) puts x into v, so caller write through v[1] writes x.
  • Caller maps writes through result onto those paths, so write through result that aliases global is global write.
  • Must-alias: two values whose points-to sets hold same single exact origin, and that origin is one object per call.
  • Allocation site inside loop or recursion makes many objects: its origin gives may-alias only.

Provenance

Doubt test (findings.md) needs to know where open type comes from.

Each unit argument has one provenance:

  • Opaque: Corset chose its type and code did not. Its data gives blind spots only.
    • Argument without stand-in (declared narrower than Any); type variable with bound.
    • Stand-in with open part: FunctionStandIn, array stand-in with open element, struct stand-in whose parameter took its bound (types.md).
  • Opt-out: source declares ::Any; declared concrete type with Any parameter (types.md, Explicit Any). Its data gives no finding and no blind spot.
  • Code: every other argument, untyped argument and type variable without bound included. Compiler sees same open type.
  • Unit that calls reach keeps caller types. Only function stand-in and array stand-in with open part are opaque there.

Sources carry provenance through engine. No separate taint pass.

  • code doubt holds sources: parameter bits, OPAQUE (FunctionStandIn) and INHERENT (doubt in code itself).
  • Open dispatch (step 7) takes sources of each operand whose type is no dispatch element.
  • Caller place gives its parameter. Global, or more than one fresh object, gives INHERENT. Chain to operand adds its own sources.
  • Value without object source takes derived sources: type values and computed numbers hold no object. Objects decide when they give a source.
  • Call result with open type derives sources of call operands with open type: eltype(a) and w .* b keep opaque source of open element.
  • Argument with open type gives its parameter. Static parameter gives each parameter whose declared type holds it. Phi and pi nodes join sources of their values.
  • Last fixpoint round records accesses: early round with sources still unknown adds no doubt in code.
  • Callback record keeps targets only: its arguments give object sources alone.
  • Two code doubts join sources, along chain and across chains. Callee summary maps parameter sources to sources of call arguments.
  • Root unit resolves sources: code source gives possible. Else opaque source gives blind spot open dispatch on opaque data. Else no access.
  • Unresolved call has doubt in code itself: unknown foreign call, builtin with splat, splat of other collection, splat that contract cannot place, invoke without constant method.
  • invoke without constant method on contract function takes contract: contract covers every method (Tuple{typeof(x)} in Base logging).
  • Provenance covers argument and every place below it. Argument with open part is opaque, so open type that code declares below it gives blind spot.
  • Contract write on argument that admits consumed iterator (iterate(x::Any)) takes sources of that argument: its type decides write.
  • Provenance judges doubt from open dispatch only. Writes code performs, and resolved, joined or contract writes, keep certainty on every origin: f(x::Any) = setfield!(x, :n, 0) writes x.

Calls

Resolution of each call statement, first match wins:

  1. Builtin or intrinsic: transfer function (setfield!, memoryrefset!, setglobal!, swapfield!, modifyfield!, replacefield!; _apply_iterate unpacked).
  2. Foreign call: table of known C functions (memmove writes destination; runtime type queries read only). Unknown: possible write on pointer and object operands, doubt in code.
    • MPFR and GMP entries come from C headers: pointer to non-const is written, pointer to const is read (mpfr_srcptr, const char *). Generator: gen/foreign/generate.jl; output: src/Effects/foreign_gmp_mpfr.jl.
    • Symbols: every MPFR and GMP function that Base and SpecialFunctions call, plus five numeric extras. The whole header holds about 800 functions; each one needs vetting for global state.
    • Hand entries (calls.jl) cover variadic functions and pointer results. Left open: functions that write C global state (mpfr_set_emax, mpfr_set_emin, mpfr_clear_flags, GMP allocator hooks).
    • PCRE2 entries cover functions that Base regex code calls, by PCRE2 API manual. Match writes match data and JIT stack of match context.
    • No prefix rule: unknown mpfr_ or __gmp name stays open, because wrong entry gives false definite write.
    • CI lacks the headers. The generator does not run there; committed file is the source of truth. Test compares it with hand classification.
  3. Static call (one method matches, or Core.invoke with constant selector): callee summary. No method matches: call throws, so code after it is dead. Summary per variant: instance plus constant arguments callee uses as field name. getproperty(x, :a) keeps field a. Constant Bool argument that callee uses as branch condition also makes variant. Variant code drops blocks branch never reaches. HAMT.path(trie, key, h, false) skips copy-on-write store, so ScopedValue read writes nothing. Julia inference resolves the same constant.
  4. Static call on callable holding object below caller parameter: callee stores and result apply now. Accesses go into callback record for caller.
  5. Run-time dispatch in package code with at most 3 matching methods: join their summaries. All agree: their certainty. Disagree: possible. Access that some members lack takes sources of open operands, as open dispatch does: operand types pick member. Blind access of one member and exact access of another disagree: join gives possible.
  6. Base interface function with documented contract (setindex! writes collection; length reads only; view result lies within array). Breach in package method is finding.
  7. Else open: possible write on operands; result may point into operands, one direction, and to unknown.
  • Splat of tuple or array with unknown length: dispatch on Vararg of element type. Callee parameters past fixed operands take any element.
  • Splatted tuple slot has unknown position, so caller tuple collapses to deep. Splat of other collection stays open: its iterate runs.
  • Instance specializes on call argument types. Callable type known to caller is concrete in callee too, so step 3 reaches its method.
  • @invokelatest f(x) with constant GlobalRef resolves as call f(x), keywords included (Base.invokelatest_gr).
  • Constant binding has its value in analysis world. IR world range can start before binding exists: @invokelatest reads binding in latest world.
  • Callback record keeps write path short. Tuple foreach wraps closure in foldl reducers: closure writes lie three steps below reducer.
  • Caller maps record to its own objects. Callable still holding object below caller parameter passes record to next caller.
  • Root unit has no caller: its verdict resolves records left in its summary.
  • Record with fresh argument applies now: caller merges fresh objects of callee into one, so record would lose them.
  • Join resolves records of its members. Member disagreement on access gives possible.
  • Recursion repeats record on same targets: record applies once.
  • Callable of abstract type stays open (step 7): solve reached no dispatch for caller type.
  • Steps 5 and 6 assume methods loaded now. Write they find keeps certainty. "Writes nothing" from them is at most possible.
  • Contract: first and generic isempty start iteration of argument (isempty docstring warns). Type with own isempty or isdone method uses its summary.
  • Contract entry holds only behavior Base documents. Base type that writes where others read (iterate on Iterators.Stateful) gives possible write when operand type admits it.
  • Query (comparison, size, predicate, arithmetic) reads arguments. Its result is new value.
  • Alias query (convert, getproperty, keys, max, conj, adjoint) reads arguments. Its result may point beneath them.
  • Element query (getindex) result is element of collection or lies beneath it, never in indices.
  • Iteration (iterate, first, only, isempty, in) reads like element query. Iterators.Stateful, Channel and EachLine get possible write.
  • Write contract (setindex!, push!, append!, resize!, pop!, copyto!, merge!) writes first argument and stores or copies elements into it.
  • Collection whose eltype points to no object (Vector{UInt8}) takes no stored object: Julia converts value at store. Foreign call table keeps every store: C pointers are untyped.
  • Function with callable-first form (get, get!, merge!): contract holds only when first argument cannot be callable. Else call stays open.
  • Keyword call of contract function: keyword tuple takes rest role. Contract needs rest role that only reads.
  • Keyword callable (by) runs as callback, so keyword call with callable value stays open.
  • Logger interface (AbstractLogger): shouldlog, min_enabled_level and catch_exceptions are queries.
  • handle_message reads message and keywords. Logger takes IO write: message goes to its sink.
  • Contract keeps no record of logged values: Test.TestLogger stores them, Base documents no store.
  • Query result that may alias every argument tripled JSON effects time and changed no verdict.
  • Open call (step 7) whose open operands come from opaque and opt-out arguments only: no finding (Provenance). Opaque argument counts on coverage line: open dispatch on opaque data.
  • Other open call: doubt in code, possible finding.
  • Limit 3 is compiler max_methods, never below. Limit 8 reached 20 times more instances on Distances.
  • Library code joins nothing: its run-time dispatch stays open (step 7). Joins there raised possible share and cost most time.

Stand-in cuts

  • Cut: call or store statement live at declared signature and dead at stand-in signature. Engine never sees it, so unit summary carries cut.
  • Causes: call that fails on stand-in only, whose callee engine never sees; type test that stand-in decides (x isa BigFloat && (STATE[] += 1)).
  • inference stage finds cuts: units with dead call or store statements first, then declared-signature inference of those units only.
  • Failure check of units gives failing calls: model-type inference decides them. Throw helpers fail on every signature, so they are never cut.
  • Package call that fails on stand-in only gets no failure-check spot, but stays cut: stand-in can dispatch to other method.
  • Package units and library instances count both causes, with model-type check for library instances.
  • Base, Core and stand-in methods count failing calls only: Base keeps documented contracts, so its type branches keep same effects (findings.md, Confidence and blind spots).
  • Generated code differs per signature. Its statements match no statement of other signature, so generated method clears no cut.
  • Callers inherit cut. Method with cut is incomplete. Verdict none with cut goes to coverage line: stand-in cuts path.
  • Blind spot points at first cut statement, else at first call whose callee carries cut.
  • Definite and possible writes keep certainty with cut.
  • Compiler effects of stand-in instance skip code past cut. Shortcut and compaction treat instance with cut like claim (Compiler effects).
  • Library cut check runs only on instance that holds stand-in: method outside Base, or call that can fail (not nothrow, or method with try). Caught failure keeps nothrow.

  • Kind comes from types along place path, root first: first IO gives IO, AbstractRNG gives RNG argument.

  • Lock, Condition and Semaphore on path give synchronization. Path without such type gives memory write.

  • Write to RNG fields of Task (rngState0 to rngState4): default RNG. Other write to Task, task_local_storage included: task-local state.
  • ScopedValue read: read of ScopedValue object or of current task scope.

  • Lazy init and audited internal state come from audited table of Base types and methods only:
    • Table keys holder type and field, or method. Listed entry sets kind before path types.

Release balance

Summary keeps hold count per resource place at normal exit and at throw exit. Count is exact (acquires less releases), unknown, or blind.

  • Resources: lock, Semaphore slot, file that open returns. Resource place: one target of operand, exact caller place or fresh object.
  • Count key: resource place and resource kind. Fresh IOStream holds file and own lock: they count apart.
  • Merged fresh objects of callee count together: open result is one of them.
  • Operand with other targets: blind spot release pattern.
  • Primitive table: lock, unlock, trylock on lock; acquire, release on Semaphore; open with IOStream result; close on IOStream.
  • Table also: wait(::Condition) releases lock and takes it again.
  • Engine never reads lock, semaphore or wait bodies. It reads open and close bodies for their IO.
  • Base libuv lock (iolock_begin) holds no Julia object: engine skips it.
  • lock(f, l), open(f, path) and @lock l expr need no entry: each releases in finally, which dataflow balances.
  • trylock gives blind spot release pattern. Count that follows its result comes later.
  • Dataflow over CFG blocks. Statement that may throw (compiler nothrow off) inside try has edge to its catch block.
  • Block keeps at most 4 paths: counts and branch conditions taken. Fifth path joins all paths into one.
  • Branch on condition that path took before takes same side: l && lock(x) … l && unlock(x) balances (Base @_lock_ios).
  • Condition is forgotten when loop runs its statement again.
  • Primitive that throws: acquire takes nothing, release still counts. unlock throws only when lock is not held.
  • Join of different counts gives unknown; count that grows round a loop gives unknown.
  • Throw exit: statement that may throw outside every try. Its count joins into throw-exit count.
  • Call applies callee counts on caller places like writes: through join and callback record. Callee throw-exit count joins at call statement.
  • Normal-exit lock or semaphore count not 0 on argument or global: lock write. Exact count gives definite; unknown from join gives possible.
  • F98 (unguarded-release) fact: statement throws outside every try while method holds resource. Release is skipped.
  • Hold comes from own acquire or callee normal exit. Callee throw-exit count alone gives none: finding goes to method that acquires.

Process model

  • One process per run. Corset loads target into its own process, as Aqua.jl and JET do, so later stages read compiler state directly.
  • Fresh process only: no Corset.check() inside runtests.jl. Test code would change method table, and --code-coverage changes optimized IR, so findings would depend on what ran before.
  • Command line always builds temporary environment: nameless project that develops target by path, starts from target Manifest, and adds test dependencies and Corset by path. Every target version stays when Corset accepts it. Otherwise packages Corset shares with target move, fewest first: Corset direct dependencies, then its dependency closure. Build prints each move; coverage line counts each loaded package at other version than Manifest pins as blind spot. Target compat that blocks every move fails loud (exit 2). Cache environment by hash of Manifest, Project.toml, Julia version and Corset version.
  • Relaunch Julia with JULIA_LOAD_PATH set to that environment and @stdlib only, so default environment (@v#.#) adds no package, trigger or method.
  • Relaunched process runs with coverage and allocation tracking off, whatever flags relaunching process has.
  • Target loads after Corset, so its methods must invalidate no Corset code. Keep inferred types concrete; put inference barrier on dependency callee that infers abstract types. test/invalidation.jl checks.
  • Package stage loads in place only there and in Corset tests: Base.locate_package must give target entry file by real path. Other path is internal error: findings would describe other code.
  • Load each extension's trigger packages: extension activates only when all triggers are loaded.
  • Cache check runs before package load: unchanged rerun loads nothing.
  • Native abort kills relaunched process, and Julia try cannot catch it: LLVM UNREACHABLE in Enzyme generator that inference runs on stand-in types.
  • Relaunched process keeps crash journal: store key of each method and signature before its inference, store entry after it. Inference writes stderr to crash log.
  • Relaunching process supervises: relaunched process that dies by signal, with key in journal that has no entry, runs again. It prints one note per crash with log path.
  • Next run reads journal: entries serve as method store, so finished work stays done; crashed key gets no inference and becomes blind spot inference crashed process.
  • Run ends with internal error after 32 crashes. Julia exception never reruns: it stays internal error.

Tests

  • UI tests, as in Clippy: test/ui/<rule>/<case>.jl with snapshot of full rendered output and fixed source. Bless command updates snapshots; CI fails on diff.
  • Each footgun: positive case, negative case, fix case.
  • Property tests (Supposition.jl) on programs built from UI case statements, with expressions spliced into value positions so fixes nest. Fixed code parses and lowers when original did. On code Julia accepts, fix removes its finding and adds none; duplicate-statement compares neighbors and is exempt. Fix runs converge. Equivalent safe fix keeps parsed meaning.
  • Differential run: safe fix behaves same before and after on executed fixture. Not built yet.
  • Reference comparison: JET, fatou, LintApp.jl, ReLint.jl on fixtures, with allowlist.
  • 100% line coverage; mutation testing on rule code.

Rule contract

Main goal of rewrite: clean structure. Legacy implemented each rule on its own, so analyses repeated and code grew.

  • Each stage computes facts once per run: syntax index, array def-use, scopes, module facts, typed IR, effect summary.
  • Rule is one pure function: facts in, findings out. Rule code imports only facts API; test enforces it.
  • Rule that needs new information adds fact to its analysis. Long rule signals missing fact.
  • Registry is data: name, group, footguns, stage, fix tier. Docs page per rule comes from footgun table.

Package load

Loading runs code. Stages after package load (package, inference, effects, lifecycle, external) run only on package with name; Julia apps qualify. Scripts and nameless environments get syntax and scope. Extensions are analyzed with test dependencies installed and their triggers loaded; untested-extension reports trigger missing from them. Later: definitions-only load for scripts.

Engine loads package only when enabled rule needs stage after syntax. Load that throws becomes load-error finding (findings.md).

package facts hold live objects (Module, Method, DataType); findings stay plain data. Package code: methods and types whose module is package module (root, submodules, extensions) and whose file lies under package root. Code that other packages' macros write elsewhere is not package code.

Method span: package stage pairs each method with definition node at its file and line. Exact span when one definition node of that name starts there; line precision otherwise (@eval loops, macro output).

UI cases for rules after syntax: case directory holds package (Project.toml with name and uuid, src/). Harness loads it in test process under unique name. Fixture that extends function it does not own (piracy) adds only methods no other case calls, so later cases see same dispatch.

Incremental runs and disk cache

  • Disk cache (Cache) holds one entry per checked path: key line, then serialized analysis. Analysis holds leveled diagnostics, baseline keys, check problems, blind spots and analyzed files. Settings and baseline apply each run.
  • Key: SHA-256 of Julia version, Base.CacheFlags, checked path, serialized flags, each load path environment with Manifest and preferences, Corset source, analyzed files, and every file of project root and Manifest path entries.
  • Key reads file content, so fresh CI checkout hits. Names that start with dot and cache directory stay out of key.
  • Location: Corset scratch space analyses in Julia depot. CI that saves depot keeps cache. --no-cache turns cache off.
  • Relaunching process computes key of relaunched process (temporary environment, load path @:@stdlib) and asks cache first. Hit loads no package and starts no process. fix always relaunches.
  • Empty cache: run prints one note: first analysis can be slow; later runs reuse cache.
  • Later: syntax stage findings per file, keyed by file content hash.
  • inference stage keeps method store per checked path beside analysis entry. Store holds one entry per inferred method and signature: reached signatures, stage facts and blind spots.
  • effects run adds effects record of unit to each entry (effects.md, Solve and cache). Library summaries keep one file per partition in directory library; every environment shares it (effects.md, Solve and cache).
  • Entry holds plain data: spans, names, call signatures. Typed code stays inside stage, so no rule reads data that store leaves out.
  • Entry depends on content hash of file of its method, since spans hold byte offsets.
  • Entry also depends on lowered code of each package method that inference read through compiler edges, transitively. Lowered code holds macro output and @eval code.
  • Closure that edit renumbers has other code, so lowered code also checks what closure and keyword body names mean.
  • Edge walk passes through dependency method whose specialization names package type or function: map(f, xs) with package f depends on f.
  • Entry records generated code of each @generated instance it read. Run calls generator again and compares.
  • Store keeps no entry whose generated instance names closure or keyword body type: edit can remove that name, and then store cannot read type back.
  • Store key line hashes environment, Corset source, analyzed file list and package shape. Other key drops whole store.
  • Package shape: signature and file of each package method, struct layouts, global types and constants. Non-analyzed files in src, ext and deps count too.
  • Constant counts by value when plain (number, string, symbol, immutable struct of those), by name when function or module, else by type.
  • Type counts by layout: field names and types. Struct that edit redefines serializes as before.
  • Shape also counts text of files that hold pirate methods: any call can reach them, and walk sees no edge.
  • Run checks each entry against file hash, lowered code and generated code; infers only invalid ones; writes store with entries this run used.
  • Result stays serialized until entry proves valid: it can name closure type that edit removed.
  • Edit of one method invalidates entries of its file and entries that read its code.
  • Later, engine runs on Salsa.jl (julia-vscode, MIT; JuliaWorkspaces.jl uses it): inputs are file texts and Project.toml; derived queries are parse trees, facts and findings. Edit recomputes only dependents; early cutoff stops at unchanged facts. Salsa keeps tables in memory only; disk cache starts new process warm.
  • Inference runs inside compiler, outside Salsa tracking: typed dependencies come from compiler edges between methods.
  • Later: warm daemon keeps Salsa tables and loaded package, so edit costs only its dependents.

Reference linters

JET, fatou, LintApp.jl (julialint, julia-vscode linter; its rules live in JuliaWorkspaces, vendored StaticLint) and ReLint.jl run only in Corset tests, never at lint time. All four are MIT: copy their rule code where it already implements our footgun, keeping license notice.

  • Tests run each reference on fixture corpus and compare findings with Corset. julialint emits JSON and SARIF.
  • Reference finding Corset misses: fix Corset, or record reason in allowlist (reference bug, different design).
  • Corset finding reference misses: expected. Corset is stricter by design.
  • Conflict is triage signal only; it never proves Corset wrong.

Term Meaning
footgun One problem Corset prevents. Source of truth; ID like F17.
rule Pure function from facts to findings. Unit of config, opt-out and level. Covers one or more footguns. Argus.jl Rule is different; Corset uses only Argus patterns.
kind Variant inside rule, with own message and fix.
stage Analysis step that computes facts once per run: syntax, package, scope, inference, effects, lifecycle, external. Rule belongs to last stage it reads.
fact Analysis output that rules read.
stand-in type Type Corset defines to stand for whatever type caller passes, so inference sees concrete type.
generic argument Annotation callers can fill with many types: x::Real, x::T.
overspecified type Annotation that names specific number type, AbstractFloat, or concrete container anywhere inside.
escaping value Value that leaves method: returned, or written to argument or global.
confidence definite: problem exists. possible: compiler cannot resolve doubt either.
blind spot Doubt compiler resolves but Corset cannot. Counted on coverage line; never finding.
level allow, warn or deny per group or rule.
diagnostic Finding with level applied; what Corset reports.
fix tier Risk of fix to callers: safe, likely, breaking, manual.
project kind Preset of levels and tier: library, application, script.
baseline Stored existing findings that never fail run.
opt-out # corset: allow <rule> -- <reason> comment.
coverage line End-of-run count of blind spots by cause.
order chain Moshi @data body A() < B() < C(): declares singleton variants and their order.
