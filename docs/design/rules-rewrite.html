Principles

Rules every design choice follows, and what Corset does not do.

  • When unsure, do what Rust and Clippy do.
  • Compute each expensive step once per run. Share output with every rule.
  • Footguns are source of truth. Checks group footguns by analysis they read. User-facing group is metadata only.
  • Give each finding confidence: definite (problem exists) or possible (problem not ruled out). One setting filters them.
  • Map every finding back to source bytes. Fixers edit lossless syntax tree.
  • Check is small query over shared facts. It never parses, lowers, loads or infers by itself.
  • Every finding explains itself: cause spans, one-line reason, concrete fix. Rust compiler errors set bar.
  • Cache findings on disk. Unchanged code is never analyzed twice, across restarts too.
  • Keep linter process warm. Load target package once. Infer each package method once; every typed check shares result.
  • Read typed IR from native compiler at lint time. Other linters (JET, fatou, LintApp.jl, ReLint.jl) serve only as test references and code sources.

Non-goals

  • Formatting: Runic or JuliaFormatter own it.
  • Running package tests, or reading signatures from them.
  • Analyzing dependency code, Base included. Code that macros expand into package counts as package code.
  • Julia versions older than latest release.
  • Security sandbox around package code. Corset loads code its user chose to lint.
  • Version 1: language server; race and ownership analysis. Shape checks F68–F70 stay.

Findings

How findings are graded, filtered, configured, shown and fixed.

Four groups: correctness, performance, composability, readability. Readability holds house style: anything that makes code hard to read. Composability holds code that must work with other types and future Julia versions.

Noise is no longer reason for group. Each finding says how sure analysis is. One setting picks what to report:

finding
confidence = "definite" (default)
confidence = "possible"
definite problem
report

possible problem
skip
report

Note: Checks with both kinds: bang-convention (dispatch past candidate budget may write), type-disruption (type branch), unwritten-element and constant-array (sites fixer cannot prove).

Groups

correctness, performance, composability, readability. One group per check; banned entries name their own group.

Confidence setting

confidence sets lowest confidence finding needs to be reported. definite (default): problem exists. possible: analysis ran and could not rule problem out; includes definite findings. Gaps in Corset itself are never possible findings; coverage line lists them. likely can join between them later.

Lint levels

Clippy model: each group and each check has level allow, warn or deny; check level overrides group level. deny findings fail run; --deny warnings makes warnings fail too. Baseline findings never fail run.

Opt-out comments

# corset: allow <check> -- <reason>. Reason is required. Opt-out that suppresses nothing is error, like Rust #[expect]. Scope by position: end of line covers line; line above function, struct or block covers that item; top of file covers file.

[preferences.Corset] table in Project.toml, read through Preferences.jl. Scripts without Project.toml use defaults and command-line flags.

  • Preset sets levels: correctness deny, other listed groups warn, unlisted groups allow. Levels and tier stay overridable per project.

Fix tiers

Each fix declares tier by risk to callers; one setting picks highest tier applied automatically. Test: would anyone's code need to change?

  • safe: proven equivalent, or fixes definite bug inside method (where-binding parentheses, untyped-empty on local array).
  • likely: changes types callers see (overspecified-type: ::Float64 → ::Real).
  • breaking: changes public API (type-disruption adds array-type parameter). Ratchet absorbs new findings.
  • manual: needs human choice (new name, sum type). Shown, never applied. Later: prompt for choice in CLI, or hand off to LLM.

Messages

Model: Rust compiler errors. Each finding carries primary span, labeled cause spans, one-line reason, fix with tier, and docs link. Analyses record cause spans (where union is created, where literal enters), so checks can name cause.

Macro output

Findings inside macro expansions are reported, other packages' macros included: message marks them upstream and points at call site. Own macro: one finding at definition, with call-site count. Fixes never edit generated code. Syntax families see source as written; findings in expanded code come from families after load, placed by lowering provenance. Location without source mapping goes to coverage line.

Conventions

  • Corset supports only latest Julia release, for running and for fixes.
  • Public API: exported or declared public. Everything else is internal.
  • test/, docs/, benchmark/ are scripts: loading them runs them.
  • Baseline matches findings by check, file, enclosing definition and normalized snippet hash. No line numbers, so edits elsewhere keep matches.
  • corset explain and docs page per check follow Clippy sections: what it does, why it is bad, example, use instead, known problems.
  • Fixes keep surrounding style; formatting stays formatter's job (Runic, JuliaFormatter).
  • Additive replacement for literal uses oneunit(x), never one(x): one drops units (Unitful.jl).
  • Corset lints itself in CI from phase 1.
  • Renamed check keeps old name as alias that warns, so opt-out comments survive renames (Clippy renamed-lints list).

one-letter exemptions

Allowed: type names and type parameters (T, N); i, j, k as indices. Everything else needs descriptive name.

Types

Typed analysis: stand-in types, type-disruption, arguments, unions, sum types.

No tests

Corset never reads or runs package tests. Signatures come from annotations: stand-in types for generic arguments and struct parameters (from their bounds), declared type otherwise. See Arguments without stand-in.

Arguments without stand-in

  • Package abstract type (s::Shape): infer once per concrete subtype package defines, with stand-ins for its parameters.
  • Function argument: stand-in function returns opaque stand-in result. Method stable under that assumption is exempt: stable whenever f is. Problems method causes itself are reported. Code that uses f's result past that point is not analyzed.
  • No stand-in yet (AbstractString, AbstractDict, abstract type without package subtype) and explicit ::Any: no findings from that argument's data.
  • Unannotated method reached from analyzed caller is analyzed through caller inference. Unannotated method nothing calls is skipped; annotation reports it.
  • Analysis gaps never become findings. Run ends with coverage line: methods not analyzed and reason.

type-disruption engine

Principle: values from outside inputs are weak. Literals, constants and globals must not change result type. Inputs combine by normal promotion. Same rule as NumPy 2 for Python scalars.

Kind Inputs combine as Literal or constant Example finding
Numbers normal promotion; Int32 with Int64 gives Int64 (pass) weak: must not widen x::Int32 * 2 gives Int64
Arrays keep container kind; element types promote fresh Array must not take over container x::JLArray .+ zeros(n) gives Array
Strings (later) String is correct common type literal is String already rare; Julia already does this
Dicts, sets (later) keep container kind; key and value types promote as for arrays rare
  • Stand-in types: types Corset defines to stand for whatever type caller passes, so inference sees concrete type. Numbers: float stand-in and integer stand-in; arrays: stand-in array type. Each is ordinary well-behaved type, and promotes like narrowest real type of its kind: float stand-in absorbs Int and loses to Float64, like Float32; integer stand-in loses to Int, like Int32. Base code runs on them unchanged.
  • Inference: infer each package method with stand-in types in place of generic arguments (::Real, T <: Real, AbstractArray{T}). Use native inference and its cache. No JET, no Cthulhu, no custom interpreter.
  • Scan (family D, package methods only):
    • Literal, constant, global or type name meets input (stand-in, or overspecified argument type): report when converting it to input type would change type of escaping value: returned, or written to argument or global. Intermediate that does not escape (Float32(x * 0.5)) goes to intermediate-widening (performance). Each site gets one finding.
    • Examples: x::Int32 * 2 (Int64 vs Int32) and x::Float32 * 0.5 (Float64 vs Float32) and Float64(x) on Float32 are reported. x::Float32 * 2 and x::Int32 / 2 (Float64 either way) pass.
    • Generic x::Real runs both number stand-ins, so x * 2 is reported through integer case.
    • Escape test: own data-flow pass follows value to returns and stores. Escape analysis tracks heap objects only, so it cannot decide this.
    • Definite: narrowest Base type of kind gives concrete counterexample. Promotion rules of user number types are out of scope.
    • Overspecified argument types (x::Int32, v::AbstractVector{Float64}) are rare in libraries: overspecified-type reports them.
    • Branch on type (x isa Float64, T === Float32): report as possible.
  • Why stand-in type: Base has fast paths for Float32 and Float64. Real float probe takes them; stand-in type takes only generic path, same as user number type.
  • Base: assume Base callees preserve types; analysis is sound only modulo Base. Optional concrete probes (Int32, Float32) catch Base-caused widening such as middle(::Int32) → Float64. Collect real Base widening bugs for upstream report.
  • Scope: version 1 covers numbers and arrays (F5, F6, F16). Strings and dicts need only new stand-in type and result rule; engine stays same. Interfaces.jl can declare each kind's contract.
  • Cost (rough estimate, unbuilt): number stand-in type 100–200 lines (promotion, conversion, arithmetic, comparison, one/zero, float, math functions); expect to add methods until inference runs clean on real packages. Mixing check 100–200 lines. Source mapping through TypedSyntax.jl.
  • No tests: stand-in types come from annotations; see Arguments without stand-in.
  • Syntax check stays for hard-coded Array without template. Shared fix helper finds in-scope type source (T, eltype(x), template array).

Annotations

::Any is explicit opt-out. Abstract argument types are intended. result-conversion reports result annotation that converts, so annotations act as checks.

Explicit Any

::Any, Vector{Any}, Any[] are approved opt-outs everywhere. untyped-empty and vague-type exempt them.

Union policy (ad-hoc-union)

One policy for inferred locals, results and struct fields; argument annotations exempt. Nothing and Missing are free. Members from one module other than Base or Core form variant group. Allow at most one member outside that group.

  • Pass: Union{Circle, Square}, Union{DepA.Leaf, DepA.Node}, Union{Float64, MyPkg.ParseError}.
  • Report: Union{Int, Float64}, Union{String, Symbol}.
  • Report where union is created: merge in package method, or package declaration.
  • Union forwarded unchanged from dependency passes; confidence = "possible" reports it.
  • Message suggests Moshi.jl ADT.
  • Baseline keeps existing findings from failing CI.

Sum types: Moshi.jl

  • One package: Moshi.jl. @match matches nested values, tuples, arrays and types; @derive writes ==, hash and show.
  • Moshi detects missing variant only when unmatched value arrives (error("matching non-exhaustive")). Its src/match/verify/ module is empty. F89 and F90 fill gap at lint time.
  • Later: offer F89 and F90 logic upstream to fill Moshi verify/. Owner approves before any PR.
  • Moshi API may change; only F89 to F91 depend on its syntax.

Suggested abstract type

Always suggest Real for floats. overspecified-type uses one helper: float_to_real(typejoin(members)). Struct field fix is type parameter (x::T) only. Property test: applying any fix never creates new finding. Build general mechanism only if test keeps finding conflicts.

Hard-coded arrays

type-disruption reports hard-coded Vector/Matrix/Array construction everywhere, zeros, ones, fill included. With template array: autofix to similar(template, T, dims). Without template: message teaches caller-supplied template or array type; autofix adds parameter in breaking tier. One shared initializer fixer serves type-disruption, constant-array and unwritten-element.

Specialization count

specialization-blowup predicts from source: C finds methods that specialize on Function or Type argument; A counts distinct closures or types passed at package call sites. Compiled-instance count from precompile workload: later, opt-in.

Process model

  • One process. Corset runs inside target environment, like Aqua.jl and JET in tests.
  • From tests: Corset is test dependency; Corset.check() in runtests.jl shares package load with test suite.
  • From command line: build temporary environment from target Manifest and add Corset with every target version preserved; fail loud if any would change. Cache by Manifest hash.
  • Load each extension's trigger packages: extension activates only when all triggers are loaded.
  • Pkg resolves Corset dependencies with package dependencies, so conflict fails loudly at install. Keep Corset dependency list short.
  • Cache check runs before package load: unchanged rerun loads nothing.

Tests

  • UI tests, as in Clippy: test/ui/<check>/<case>.jl with snapshot of full rendered output and fixed source. Bless command updates snapshots; CI fails on diff.
  • Each footgun: positive case, negative case, fix case.
  • Property tests (Supposition.jl): fix creates no new finding; fix is idempotent. safe fix: fixture behaves same before and after (differential run).
  • Reference comparison: JET, fatou, LintApp.jl, ReLint.jl on fixtures, with allowlist.
  • 100% line coverage; mutation testing on check code.

Command line

Command Does

corset fix [path] [--tier T] Apply fixes up to tier (default from preset), then check again.
corset explain <check> Print check docs offline.

Flags: -A, -W, -D <check or group> set levels (Clippy style); --deny warnings; --confidence definite|possible; --format text|json|sarif; --no-cache.

Check contract

Main goal of rewrite: clean structure. Legacy implemented each rule on its own, so analyses repeated and code grew.

  • Analysis (family) computes facts once per run: syntax index, array def-use, scopes, module facts, typed IR, effect summary.
  • Check is one pure function: facts in, findings out. Check code imports only facts API; test enforces it.
  • Check that needs new information adds fact to its analysis. Long check signals missing fact.
  • Registry is data: name, group, footguns, family, fix tier. Docs page per check comes from footgun table.

Package load

Loading runs code. Typed families (C, D, E, G) run only on package with name; Julia apps qualify. Scripts and nameless environments get A, B and H. Extensions are analyzed with test dependencies installed and their triggers loaded; untested-extension reports trigger missing from them. Later: definitions-only load for scripts.

Incremental runs and disk cache

  • Engine runs on Salsa.jl (julia-vscode, MIT; JuliaWorkspaces.jl uses it): inputs are file texts and Project.toml; derived queries are parse trees, facts and findings. Edit recomputes only dependents; early cutoff stops at unchanged facts.
  • Salsa keeps tables in memory only. Disk cache stores findings (plain data) by input key, so new process starts warm.
  • Inference runs inside compiler, outside Salsa tracking: typed dependencies come from compiler edges between methods.
  • Empty cache: run prints one note: first analysis can be slow; later runs reuse cache.
  • Location: user cache directory, one entry set per project. CI saves it between runs.
  • Global key: Julia version, Corset version, config hash, Manifest hash, preferences, active extensions. Any change clears all entries.
  • Syntax families: findings per file, keyed by file content hash.
  • Typed families: findings per method, keyed by method source hash plus compiler dependency record: methods reached and method-table lookups (new, more specific method invalidates entry), struct definitions, globals. Dynamic call: key covers every method of called function. @generated method depends on whole package.
  • Run parses every file (cheap) and computes keys. Nothing changed: no package load; cached findings print. Otherwise load package and infer only invalid methods.
  • Later: warm daemon keeps Salsa tables and loaded package, so edit costs only its dependents.

Reference linters

JET, fatou, LintApp.jl (julialint, julia-vscode linter) and ReLint.jl run only in Corset tests, never at lint time. All four are MIT: copy their check code where it already implements our footgun, keeping license notice.

  • Tests run each reference on fixture corpus and compare findings with Corset. julialint emits JSON and SARIF.
  • Reference finding Corset misses: fix Corset, or record reason in allowlist (reference bug, different design).
  • Corset finding reference misses: expected. Corset is stricter by design.
  • Conflict is triage signal only; it never proves Corset wrong.

Spikes

  • S1 stand-in inference: float, integer, array and function stand-in types; per-subtype inference for package abstract types; infer every method of three corpus packages. Measure stand-in gaps, run time and count of integer-literal findings. never-succeeds must ignore calls that fail only because stand-in type lacks method.
  • S2 source mapping: TypedSyntax.jl maps typed findings to bytes, macro output included.
  • S3 scope layer: JuliaLowering does not ship with Julia 1.13 and is not registered; it lives in JuliaLang/julia as 1.0.0-DEV. Try it from source. Fallback: Meta.lower per top-level form, with line positions only.
  • S4 syntax matcher: Argus.jl shows no license. Ask author, or use own matcher on JuliaSyntax. Compare with LintApp.jl and ReLint.jl code (MIT).
  • S5 effect summary: Julia reports no per-argument writes, so build own summary bottom-up over call graph: escape analysis inside method, callee summaries at calls. Unknown callee gives possible. Internal API; pin per Julia minor version.

Quality gate

Check is on by default only when all hold:

  • Fixture per footgun: positive, negative, and fix result.
  • Any false definite finding blocks check: it is check bug. At least 90% of sampled possible findings are real problems.
  • Property tests (Supposition.jl): fix creates no new finding; fix is idempotent. safe fix: fixture behaves same before and after (differential run).
  • Message shows cause span and concrete fix; reviewed on corpus sample.
  • Run time stays inside budget in CI perf test.

Speed budget (draft): full cold run at least 5× faster than legacy on same package; syntax-only run under 2 s per 10,000 lines after startup; rerun with no changes under 1 s.

Repository bar: 100% line coverage; mutation testing on check code. Corpus: packages that already run legacy Corset, plus three registered packages of different style (numeric, data, IO).
