Principles

Principles behind every design choice, and what Corset does not do.

  • When unsure, do what Rust and Clippy do.
  • Every decision is revisable. Evidence from corpus runs and users outranks earlier reasoning; see design reviews in plan.md.
  • Compute each expensive step once per run. Share output with every rule.
  • Footguns are source of truth. Rules group footguns by analysis they read. User-facing group is metadata only.
  • Give each finding confidence: definite (problem exists) or possible (run-time values decide). One setting filters them. Corset blind spots go to coverage line only (findings.md).
  • Map every finding back to source bytes. Fixers edit lossless syntax tree.
  • Rule is small query over shared facts. Analysis stages compute every fact once per run; rule only reads them.
  • Each fact has one producer. Rule never guesses later-stage fact (type, mutability, effect, ADT variant) from syntax; it waits for that stage.
  • Rule belongs to last stage its findings need. One rule never mixes syntax footguns with footguns of later stages.
  • Fixer may read later stages when they ran. Otherwise its fix is manual.
  • Every finding explains itself: cause spans, one-line reason, concrete fix. Rust compiler errors set bar.
  • Cache findings on disk. Unchanged code is never analyzed twice, across restarts too.
  • Keep linter process warm. Load target package once. Infer each package method once; every typed rule shares result.
  • Read typed IR from native compiler at lint time. Other linters (JET, fatou, LintApp.jl, ReLint.jl) serve only as test references and code sources.

Non-goals

  • Formatting: Runic or JuliaFormatter own it.
  • Relying on package tests or precompile workloads. Facts come from source, type annotations, loaded module and inference. Package without tests or workloads gets full analysis. Code that ran before Corset changes speed only, never findings.
  • Findings in dependency code, Base included. Analysis reads dependency code freely (callee summaries, inference); only findings stay inside package. Code that package macros write counts as package code; code that other packages' macros write does not.
  • Julia versions older than latest release.
  • Security sandbox around package code. Corset loads code its user chose to lint.
  • Version 1: language server; race and ownership analysis. Thread pattern rules F68–F70 stay.

Pipeline

Analysis stages Corset computes, in pipeline order. Each stage computes facts once per run; rules read them.

Stages run top to bottom. Stage not built yet gives no facts; no rule reads it until it ships. Rule declares two stages: stage for findings and fix_stage for fixes, never earlier. Engine computes only stages selected rules need for either. scope runs after package: macro expansion needs evaluated imports and package macros. Scripts: scope evaluates imports only; unresolved macros go to coverage line.

syntaxSyntax patterns

One tree walk per file. Rules are Argus.jl patterns: syntax classes, pattern forms, templates for fixes. Walk indexes rules by pattern root kind and asks Argus to match candidate nodes only. Names read as written: Base export name means Base binding; shadowed-base reports package method that breaks this. Macro arguments read as code, except arguments with {} (stopgap, revisit later); quoted code reads as data outside $ interpolation. Parse errors become deny findings. File role fact: package module code (precompiled) or script. Project.toml facts (dependencies, extensions, test dependencies), read before load.

Findings

How findings are graded, filtered, configured, shown and fixed.

Six groups: correctness, safety, performance, composability, readability, restriction. Correctness holds code that misbehaves now: input, path or broken contract. Safety holds code that works now but lets later mistake pass silently; its fix makes Julia catch mistake. Readability holds house style: anything that makes code hard to read. Composability holds code that must work with other types and future Julia versions. Restriction holds opinionated rules: each forbids form that Julia manual or Base uses as idiom.

Noise is no longer reason for group. Each finding says how sure analysis is. One setting picks what to report:

Groups

correctness, safety, performance, composability, readability, restriction. One group per rule, banned included.

Restriction test: does Julia manual or Base use form as idiom? Then rule against form is taste: restriction. No preset enables restriction; project turns its rules on one by one, as Clippy restriction lints.

Safety test: does fix turn silent mistake into error, failed check or failed test? broad-catch fix rethrows unexpected errors; unchecked-enum fix gets exhaustiveness check.

Confidence and blind spots

confidence sets lowest confidence finding needs to be reported. definite (default) reports definite findings only; possible reports both. likely can join between them later.

Source of answer decides report. Run-time values, foreign code and methods added later stay unknown until program runs. Code, types and method table are known before run.

  • Finding: write lands below argument w past place Corset names. Doubt is only where it lands: w changes, so bang-convention keeps certainty of write.

  • Blind spot: inference gave no code (generator threw); method has more signatures than limit; argument type has no stand-in.
  • Blind spot: no call reaches untyped method; macro did not expand; computed include sits in branch, loop or function body, or loads file outside project.
  • Exemption needs proof: rule counts access Corset cannot prove exempt (balanced lock, IO or RNG write). Rare false finding takes # corset: allow.
  • Corset limits never fall below compiler limits (max_methods, union splitting).

Coverage line ends every run and counts blind spots by cause: analyzed 412 of 430 methods; skipped 18 (generated function: 2, unexpanded macro: 16). Rule that lacks fact at site reports nothing there.

Lint levels

Clippy model: each group and each rule has level allow, warn or deny; rule level overrides group level from any source. Command-line flags beat config; config beats preset. deny findings fail run; --deny warnings makes warnings fail too. Baseline findings never fail run.

Opt-out comments

Modeled on Rust lint attributes. # corset: allow <rule>, <rule> -- <reason>; reason is required. After code, comment covers that line. On own line, it covers next statement: function, struct, block or expression. # corset: allow-file <rule> -- <reason> before first code covers file, like Rust inner attribute #![allow].

Malformed comment, unknown rule, late allow-file, and opt-out that suppresses nothing are errors; they always fail run, like unfulfilled #[expect] under -D warnings. Opt-outs apply to findings before levels and confidence filter, so config change never orphans opt-out.

Parse errors

JuliaSyntax parse error is error finding at deny, outside rule table, as Ruff reports syntax errors. No level, opt-out or baseline hides it. Rules still run on recovered tree.

Load errors

Package that throws while loading gets load-error finding at deny, outside rule table, as parse-error. Primary span: deepest backtrace frame inside package source; package entry file when none. Message carries exception text. syntax rules still run; later stages skip, and coverage line says package did not load. Failed precompilation is load error too: Julia throws and loads nothing. Precompile error has no frame in package, so second load in anonymous module supplies frames; precompile-only failure points at entry file. Extension that throws gets load-error at its file; package rules still run, and coverage line counts extension. Extension whose trigger environment cannot load is blind spot.

Config

[preferences.Corset] table in target Project.toml; [Corset] table in LocalPreferences.toml overrides it key by key (Preferences.jl layout). Corset reads both files by path: target project is rarely active environment. Keys: kind, confidence, fix_tier, levels (group or rule name to level), banned (list of bans). PrecompileTools reads precompile_workload from same table; config ignores it. Each ban holds reason and one target: Argus pattern, or name regex that must match whole bound name. Unknown key, value or name is config error (exit 2). Scripts without Project.toml use defaults and command-line flags.

Fix tiers

Each fix declares tier by risk to callers; one setting picks highest tier applied automatically. Test: would anyone's code need to change?

  • safe: proven equivalent, or fixes definite bug inside method (where-binding parentheses, untyped-empty on local array).
  • likely: changes types callers see (overspecified-type: ::Float64 → ::Real).
  • breaking: changes public API (type-disruption adds array-type parameter). Ratchet absorbs new findings.
  • manual: needs human choice (new name, sum type). Shown, never applied. Later: prompt for choice in CLI, or hand off to LLM.

Macro output

Rules read code as written, macro arguments included. Code that package macro writes gets findings: one finding at macro definition, with call-site count. Code that other packages' macros write gets none, since package cannot fix it (Clippy in_external_macro). Fixes never edit generated code. Syntax stage skips quoted code outside $ interpolation, and macro arguments with {} (Argus patterns), which lowering always rejects. {} check is stopgap; revisit with general check in plan later row. Code passed through macro (@inbounds, @views) maps to exact bytes. Code macro writes itself maps to line: call-site line for macro of other file (outermost debuginfo scope), nearest line inside definition for macro of same file and @generated output. Conventions

  • Corset supports only latest Julia release, for running and for fixes.
  • Public API: exported or declared public. Everything else is internal.
  • test/, docs/, benchmark/ are scripts: loading them runs them.
  • Baseline lives in corset-baseline.toml at project root; corset baseline writes it. Entries match findings by rule, file, enclosing definition and normalized snippet hash. No line numbers, so edits elsewhere keep matches. Baselined findings stay hidden. Entry that matches no finding fails run until corset baseline rewrites file, like ESLint bulk suppressions.
  • corset explain and docs page per rule follow Clippy sections under plain headings: Description, Rationale, Example, Alternative, Limitations. Text lives in rule module docstring; registry test enforces sections.
  • Fixes keep surrounding style; formatting stays formatter's job (Runic, JuliaFormatter).
  • Additive replacement for literal uses oneunit(x), never one(x): one drops units (Unitful.jl).
  • Corset lints itself in CI from phase 1.
  • Renamed rule keeps old name as alias that warns, so opt-out comments survive renames (Clippy renamed-lints list).

one-letter exemptions

Allowed: type names and type parameters (T, N); i, j, k as indices. Everything else needs descriptive name.

Types

Typed analysis: stand-in types, type-disruption, lost narrowing, arguments, unions, sum types.

No tests

Corset never reads or runs package tests. Signatures come from annotations: stand-in types for generic arguments and struct parameters (from their bounds), declared type otherwise. See Arguments without stand-in.

Array stand-ins

  • Array argument takes array stand-in shaped as its annotation: stand-in kind replaces container, element and dimensions keep annotation bounds.
  • AbstractVector gives ArrayStandIn{<:Any, 1}. AbstractArray gives ArrayStandIn with open dimensions. AbstractVecOrMat gives one stand-in per member.
  • Element bound below Any that number stand-ins fit takes them, as number argument does: AbstractVector{<:Real} gives float and integer elements.
  • Number stand-in elements keep float promotion that type-disruption reads (xs .* 0.5).
  • Other element stays open (ArrayStandIn{<:AbstractString, 1}). Concrete Any element decides element-type calls: oneunit(eltype(xs)) fails, so loop body is dead.
  • DenseArray and StridedArray bounds take DenseStandIn.
  • Open stand-in is not concrete. Call reaches untyped method when each argument type is concrete once its variables take their bounds (view of open stand-in too).

Arguments without stand-in

  • Package abstract type (s::Shape): infer once per concrete subtype package defines, with stand-ins for its parameters.
  • Struct parameter takes every stand-in its bound fits, package struct stand-ins included (Outer{S <: Inner}).
  • Struct parameter no stand-in fits takes its bound. Field of type Any acts as ::Any argument: its data gives no findings.
  • Struct that bound makes empty gets no stand-in: Sized{N} with N = Any has field type Union{}.
  • Union or abstract argument takes first stand-in of each struct before second of any, so cut at signature limit reaches most structs.
  • Macro that rebuilds struct (@concrete struct) gives constructors its own file; struct ties to its form by name.
  • Function argument: stand-in function returns Any (inference barrier). Its call has unknown compiler effects, so compaction keeps it; effects reads it as call of function value without name. Method stable under that assumption is exempt: stable whenever f is. Problems method causes itself are reported. Code after f's result stays analyzed; values from that result give no findings. Opaque result type truncates inference frames.
  • No stand-in yet (AbstractString, AbstractDict, abstract type without package subtype) and explicit ::Any: no findings from that argument's data.
  • Unannotated method reached from analyzed caller is analyzed through caller inference: inference stage keeps explicit worklist of package frames reached from stand-in callers. Unannotated method nothing calls is skipped; annotation reports it. Expect low coverage on unannotated packages (Distances: 165 of 283 methods) until annotation fixer runs.
  • Method Corset cannot analyze is blind spot: coverage line counts it with reason.

type-disruption engine

Principle: values from outside inputs are weak. Literals, constants and globals must not change result type. Inputs combine by normal promotion. Same rule as NumPy 2 for Python scalars.

Each is ordinary well-behaved type, and promotes like narrowest real type of its kind: float stand-in absorbs Int and loses to Float64, like Float32; integer stand-in loses to Int, like Int32. Base code runs on them unchanged. Array stand-in has OneTo axes and column-major memory: rules about axes or memory order read declared argument type, never stand-in.

Input absorbs weak value: with input swapped to Float64, conversion changes nothing. Builtins (getfield(t, 2)) change no result type.

lost-narrowing scan

  • Lowering stores value of a && b in variable when guard || exit or if !(…) branches on it. Inference narrows variable on branch of type test only, so narrowing ends inside chain.
  • Lowering branches directly on || chain, ternary condition and if a && b, so narrowing stays there. Condition stored in variable (ok = a || b) loses it.
  • Scan (inference stage, Narrowing): follow control flow of typed code as inference does. Also carry what each variable that holds condition proves when true and when false.
  • Type tests: x isa T with constant T, x === nothing, x !== nothing, isnothing(x), and their negation.
  • Loss: read where scan proves narrower type than inference gives at start of block. Inference keeps variable types per block, so check needs no second inference.
  • Exception handler proves nothing: it can run after any statement of try body.
  • Report loss when test maps to term of && or || chain; other losses give no finding. One finding per test; first read is cause span.
  • Fix: one guard per term, safe. Guard must be own statement with unused value, exit must leave block (return, continue, break, throw, error, rethrow), and no comment may sit inside. Else manual.

Annotation transition

Helps unannotated package reach full annotations. annotation fixer guesses types; message shows evidence for each guess.

  • Evidence, strongest first: argument types at package's own call sites, inferred through annotated callers; default values; struct fields argument flows into; operations body applies (arithmetic gives Number, indexing and length give AbstractArray).
  • Widen evidence to family: numbers to Real (Integer when all integer), arrays to AbstractVector{<:Real}, struct to nearest abstract supertype; union of at most three families. Keep guess only when it holds every observed type. Scheme comes from legacy typed fixer.

  • Argument guess with call-site evidence: tier breaking, since narrower annotation can reject callers. Body-use evidence only: tier manual.

Hard-coded arrays

Index proof (one-based-range)

Each index into array needs proof unless inferred axes type of array is OneTo. Rule asks code for proof; it never assumes one.

  • Array stand-in stands for every caller array, offset arrays included. Its OneTo axes hide offsets: inference folds firstindex(x) into literal 1.

  • So effects stage infers each method with array stand-in again, with offset stand-in (OffsetArray of array stand-in) in its place.

  • Proof runs on that code. Inferred axes type there decides: view(x, 2:3) has OneTo axes, view(x, :) keeps axes of x.

  • Method store keeps facts of second inference with unit record. Entry also reads package methods that second inference reached.

  • Index of x: value that stays in index range of x. Rule follows SSA values of typed code.

  • Sources: eachindex(x), axes(x), keys(x), pairs(x), firstindex(x), lastindex(x), begin, end, LinearIndices(x), CartesianIndices(x).

  • Base results that index x: findfirst, findnext, findall, argmin, argmax, searchsorted*, sortperm.

  • Closure: i ± k, prevind, nextind, min, max, clamp, midpoint lo + (hi - lo) ÷ 2, range between indices of x, loop variable over such range.

  • Index argument stays caller's index through i ± k. Choice (min, clamp, range bound) of argument and literal is absolute: x[1:i] needs proof.

  • In choice, index argument matches any array: min(i, lastindex(x)) indexes x, min(i, firstindex(y)) indexes y.

  • Proof reads lowered and typed code for indexing: inference with one-based stand-in can drop branch on firstindex(x) == 1.

  • Crash journal records offset inference: generator can abort process on new types. Crashed key gives blind spot, as does no code.

  • Generator that gives other code for offset stand-in: blind spot. Spans of first inference fit only same lowered code.

  • Arguments that share type variable (x::T, y::T) take offset stand-in together.

  • Midpoint (lo + hi) ÷ 2 is no proof: sum of two indices overflows on axes near typemin.

  • Other arithmetic (*, ÷, mod, shifts) gives absolute number: heap parent i ÷ 2 assumes one-based axes.

  • Two arrays: eachindex(x, y) throws on different axes, so it gives index of both. So does guard axes(x) == axes(y) || throw(...).

  • Same axes: similar(x), similar(x, T), copy(x), zero(x) and broadcast of x with scalars have axes of x. Index of x indexes them.

  • Guard Base.require_one_based_indexing(x) proves every index of x after it.

  • checkbounds is no proof: absolute index inside shifted range passes it and reads wrong element.

  • Index argument (f(x, i) = x[i]): method carries contract: argument i indexes argument x at index position p of n. Public function carries contract, as getindex does. Arithmetic of several index arguments (x[i + delta], f(x, i + delta)) carries no contract: blind spot.

  • Package call with array stand-in operand records what each operand indexes: other operand and dimension (axes agreement included), index argument of caller, absolute index, index of other array, or unknown source.

  • Rule matches call sites against contracts of callee methods. Index argument of caller passes. Absolute index or index of other array gives definite; unknown source gives possible.

  • Call that passes index argument of caller with array argument of caller gives caller same contract. Rule closes contracts over package calls.

  • Contracts and call-site facts come from offset inference of each unit alone: callee facts never enter caller record, so method store keeps units apart.

  • Unit that calls package function with array stand-in operand gets offset inference, as unit that indexes does. Package method on Base function counts. Lowered code counts too: one-based inference can drop call. Slot aliases (g = f, ys = xs) count, and call result holds arrays of its operands (copy(xs)). Callee with one alternative that no global names (call result as getfield(M, :f), or argument) counts as package function.

  • Absolute index (literal, length, size, enumerate counter, index of other array): definite.

  • Index of unknown source (stored indices, unchecked arithmetic): possible.

  • Stored indices into input array: copy input to Vector at construction, or guard. Both give proof.

  • Tests run fixtures on EvilArrays.jl arrays too: code with proof gives same result.

Roots

Each SSA value gets a set of roots: the caller-visible objects it can hold or lie beneath.

  • Root: parameter, global binding, or fresh. Fresh objects are local: writes to them are no facts.
  • Path: field name or element below root. Path collapses to deep past 8 steps.
  • getfield, getproperty with constant name and getindex add a step to roots of their first operand.
  • Load from fresh object gives roots it holds. Nested fresh objects flatten: outer object holds roots that inner objects hold.
  • Fresh object can also hold untracked objects: fresh, or unknown. Load from such object can be fresh, so writes through it are possible.
  • Mutable literal in code, such as interpolated object, is global state: Elsewhere root.
  • Phi and pi nodes join roots of their values.
  • Alias table: library functions whose result can be an operand or lie beneath it. Result keeps places of each non-callable operand.
    • Table: view, reshape, vec, parent, transpose, adjoint, keys, values, pairs, first, last, only, identity, skipmissing, iterator wrappers (zip, enumerate, Iterators.*).
    • Pointer conversions before foreign call: pointer, cconvert, unsafe_convert.
    • .= target (a[i] .= x) and @views: dotview and maybeview give view for array with non-scalar index. Else they call getindex: element step.
    • view, dotview and maybeview result lies beneath array operand only. It holds index operands: values[indices] .= 0 writes values.
  • Choice table: result is one of the operands, callable objects included, so it joins their values: something, coalesce, max, min, ifelse.
  • convert result is its operand, or new object as for other call.
  • typeassert result is its operand. Lowering adds typeassert on each return of method with return type.
  • Constructor, tuple and vector literal results hold their operands: Ref(x) holds x. Literal ([x], T[x]) converts element not of its element type, so it can hold new object. Package method on literal syntax (SA[x]) is package call.
  • Iteration: result of iterate and indexed_iterate holds element of iterated operand. Element step for array, dictionary, set and tuple; deep for other iterator.
  • Element table: result is element of container operand, or other operand (get(d, k, default)).
  • getindex with constant integer index into tuple loads position step; other index loads element step.
  • getindex of array with range, array or Colon index copies part (a[1:2]): new object, as copy.
    • Table: get, get!, getkey, pop!, popfirst!, popat!, maximum, minimum, reduce, foldl, foldr, rand, take!, fetch.
    • Container: first operand, or second after leading callable or AbstractRNG (get(f, d, k), rand(rng, xs)).
    • Lookup default: third operand of get, get!, getkey, pop!, popat! without leading callable.
    • Result of leading callable can be fresh, or object it captures. rand with dimensions gives new array of elements.
    • Keyword call can give new array of elements (dims) or keyword value (init).
    • take! and fetch give element of Channel. Other result lies beneath operand or is new: take!(::IOBuffer) can share buffer.
  • Result of other call, package call included, is fresh. It can hold untracked objects, and deep place of each operand whose type can hold pointing objects (copy, filter).
  • Result that is package call operand, or lies beneath it, needs package record of result roots. Later: callers map them.
  • Result with isbitstype type holds no root. Result whose type holds no pointing object holds no root inside.

Writes

Write sources, in order:

  1. Builtin store: setfield!, setglobal!, memoryrefset!, swapfield!, modifyfield!, replacefield!, setfieldonce!. Definite write on roots of target. Pointer store intrinsics (pointerset) write target or below.
  2. Call to function whose name ends in !. Written operand follows Julia style guide argument order:
    • Skip leading callable (Function, Type), IO and AbstractRNG operands. First other operand is written: definite.
    • Nothing member of union drops first: rng::Union{Nothing, AbstractRNG} is RNG operand. Its write is possible.
    • Skip operand of type that refers to no mutable object too: no call can write it. rand!(rng, Normal(), x) writes x.
    • rand!, randn! and randexp! write first array operand: Distributions adds rand!(rng, s, x). Distributions helpers _rand! and __rand! keep that order; other underscore helper follows ordinary rule.
    • !! function (BangBang.jl) writes operand when it can, else returns new value: possible.
    • Skipped IO operand takes IO write; skipped AbstractRNG operand takes RNG argument write.
    • No operand left: possible write on keyword values (f!(; items)); without keywords, definite write on unknown global state (Random.seed!()). Skipped IO, RNG or immutable operand counts as written operand: take!(io) writes io only.
    • Position table holds exceptions: ldiv!(A, B) and lmul!(A, B) write B.
    • ! call stores its other operands into written operand: push!(v, x) puts x into v. Later load from v can give x, also when v is caller place.
  3. Exception table: library functions without ! that write. Iteration of stateful types (Iterators.Stateful, Channel, EachLine, Iterators wrappers of them), IO functions on IO operand, locks and conditions, task switches, RNG functions.
    • first, only and consuming table on stateful iterator write it or below. Iterators.flatten of stateful iterators consumes them.
  4. Foreign call: possible write on roots of pointer and object operands.
  5. Closure built in method (new of closure type): call that can invoke it writes through captured fields onto captured operands, with their certainty.
    • Invoking calls: direct call, and function that calls its function arguments (foreach, map, leading callable of ! call).
    • Builtins, constructors, tuples, alias functions and stored operands of ! calls never invoke it. Closure that only escapes writes nothing in its builder.
    • Call that compiler proves effect_free runs no closure that writes caller state (hash(f)). @assume_effects in method or its callee voids that proof.
    • Closure body write below global binding, or assignment to global, writes that global. Keyword tuple of Core.kwcall passes its closures on.
    • Call fact keeps closure write kinds apart from other writes of call, such as consumed stateful iterator. They count writes to fresh captured objects too.
  6. Other call: no write. Call of function value without name (callable argument or field) writes nothing too: Base names higher-order functions without ! (map, foreach).
  • Value with more than one root gives possible write on each root: branch decides which object changes.
  • Write in package code keeps certainty on every root: f(x::Any) = setfield!(x, :n, 0) writes x.
  • Writes before throw stay. Writes to fresh objects inside error paths are local.
  • Compiler effect_free on unit proves no write: definite none. Else no write event gives none by name trust: at most possible none.
  • Stand-in signature gives no proof: compiler effects describe stand-in only. @assume_effects :effect_free on method, block in it, or direct callee gives none either.
  • Code coverage voids effect_free of tracked files: inference counts coverage counters as effects. Tests of proof rules run with coverage off.

Reads

Origins and points-to

  • Origin: abstract object. Kinds: caller place (parameter or global path), allocation statement, unknown.
  • Constant object in code counts as unknown: write to it is definite. Fresh objects of callee merge into one allocation at call statement.
  • unknown: object open call can return that no operand names, global included. Write to it is possible global write.
  • Current task is unknown without doubt: write to its fields is certain global write.
  • One unknown origin stands for every outside object, so values stored into it take code doubt.
  • Callee object outside its caller places maps to unknown and to each object caller stored into it. Each keeps doubt of its chain, at least code.
  • Such caller object also maps to deep of its root: callee may reach below it.
  • Task state access (task_local, default_rng, scoped_read) on Elsewhere stays on unknown: it names current task. Every other kind reaches those objects.
  • Audited access on Elsewhere stays on unknown too: audit names Base object, such as scheduler fields of current task.
  • Base methods access scheduler fields of Task as audited state. Property accessors (setproperty!) are exempt: their access belongs to caller.
  • Package write to scheduler field of task, such as t.sticky = false, stays task-local state.
  • Path: field name or element. Path follows declared field types.
  • Path collapses to deep at step into concrete type it already passed (recursive type), at third abstract step in a row, or past 8 steps.
  • Place says where access lands; certainty says whether it happens. deep w is coarse place: write below it still changes w.
  • Field name comes from concrete type, array stand-in family or Array family. Other struct family (Object{K, V} where …) gives field position.
  • Memory backing belongs to its owner: field of type GenericMemory or GenericMemoryRef adds no step. Write to Vector elements writes Vector.
  • Callee or table access to owner may land on its memory alone or owner alone: memory behind it gets possible access (pop! of Base.wrap(Array, m, n)).
  • Memory address (Ptr, MemoryRef) that callee returns names memory behind fresh owner: write through it writes that memory.
  • Ptr value holds origins of object it points into, so foreign call through pointer writes that object. Data pointer of memory holds memory.
  • Constant null pointer global (C_NULL) points into no object.
  • Points-to: inclusion-based, field-sensitive, over SSA values and origin contents. Heap is flow-insensitive; SSA values keep flow.
  • Unification is rejected: it merges unrelated objects at each unknown call.
  • Write: statement that stores into origin content, or callee summary write mapped through call operands.
  • Each origin in points-to set carries doubt: none, code or blind. Join keeps least doubt per origin.
  • Open call on chain gives code.
  • Merge of callee fresh objects is exact when they form one object: each fresh object but one backs another.
  • Array and its Memory form one object: merged object backs itself.
  • Exact merge also needs each slot to hold stores of one fresh object at most.
  • Inexact merge gives blind: caller store into one merged object would show in the others.
  • Collapsed path and load of non-constant slot add no doubt: object they reach lies below same root.

  • Exempt kind needs proof, as balanced lock use does. Raw write into IO memory below deep w is memory write: # corset: allow covers it.
  • Access takes most doubt of effect and chain. None gives definite; code gives possible.
  • blind gives blind access with cause alias: blind spot, counted on coverage line only.
  • Summary per parameter and global: read and write of top object, each path, and deep. Each has certainty and cause span.
  • Access says whether it covers every place below too. Open call covers whole object graph below each operand.
  • Access below fresh object covers caller objects in its slots: open call on (x,) writes below x.
  • Caller maps callee deep place: caller place below argument keeps access certainty. Caller object inside fresh argument gives blind: callee may leave it unchanged.
  • Summary also gives result origins as parameter and global paths: result aliases. Fresh result keeps its fields: view(A, 1:2) result holds A.
  • Summary gives stores callee makes between caller objects: push!(v, x) puts x into v, so caller write through v[1] writes x.

  • Allocation site inside loop or recursion makes many objects: its origin gives may-alias only.

Provenance

Doubt test (findings.md) needs to know where open type comes from.

Each unit argument has one provenance:

  • Opaque: Corset chose its type and code did not. Its data gives blind spots only.
    • Argument without stand-in (declared narrower than Any); type variable with bound.
    • Stand-in with open part: FunctionStandIn, array stand-in with open element, struct stand-in whose parameter took its bound (types.md).
  • Opt-out: source declares ::Any; declared concrete type with Any parameter (types.md, Explicit Any). Its data gives no finding and no blind spot.
  • Code: every other argument, untyped argument and type variable without bound included. Compiler sees same open type.
  • Unit that calls reach keeps caller types. Only function stand-in and array stand-in with open part are opaque there.

Sources carry provenance through engine. No separate taint pass.

  • code doubt holds sources: parameter bits, OPAQUE (FunctionStandIn) and INHERENT (doubt in code itself).
  • Open dispatch (step 7) takes sources of each operand whose type is no dispatch element.
  • Caller place gives its parameter. Global, or more than one fresh object, gives INHERENT. Chain to operand adds its own sources.
  • Value without object source takes derived sources: type values and computed numbers hold no object. Objects decide when they give a source.
  • Call result with open type derives sources of call operands with open type: eltype(a) and w .* b keep opaque source of open element.
  • Argument with open type gives its parameter. Static parameter gives each parameter whose declared type holds it. Phi and pi nodes join sources of their values.
  • Last fixpoint round records accesses: early round with sources still unknown adds no doubt in code.
  • Callback record keeps targets only: its arguments give object sources alone.
  • Two code doubts join sources, along chain and across chains. Callee summary maps parameter sources to sources of call arguments.
  • Root unit resolves sources: code source gives possible. Else opaque source gives blind spot open dispatch on opaque data. Else no access.
  • Unresolved call has doubt in code itself: unknown foreign call, builtin with splat, splat of other collection, splat that contract cannot place, invoke without constant method.
  • invoke without constant method on contract function takes contract: contract covers every method (Tuple{typeof(x)} in Base logging).
  • Provenance covers argument and every place below it. Argument with open part is opaque, so open type that code declares below it gives blind spot.
  • Contract write on argument that admits consumed iterator (iterate(x::Any)) takes sources of that argument: its type decides write.
  • Provenance judges doubt from open dispatch only. Writes code performs, and resolved, joined or contract writes, keep certainty on every origin: f(x::Any) = setfield!(x, :n, 0) writes x.

Calls

Resolution of each call statement, first match wins:

  1. Builtin or intrinsic: transfer function (setfield!, memoryrefset!, setglobal!, swapfield!, modifyfield!, replacefield!; _apply_iterate unpacked).
  2. Foreign call: table of known C functions (memmove writes destination; runtime type queries read only). Unknown: possible write on pointer and object operands, doubt in code.
    • MPFR and GMP entries come from C headers: pointer to non-const is written, pointer to const is read (mpfr_srcptr, const char *). Generator: gen/foreign/generate.jl; output: src/Effects/engine/foreign_gmp_mpfr.jl.
    • Symbols: every MPFR and GMP function that Base and SpecialFunctions call, plus five numeric extras. The whole header holds about 800 functions; each one needs vetting for global state.
    • Hand entries (calls.jl) cover variadic functions and pointer results. jl_get_current_task returns unknown without doubt. Left open: functions that write C global state (mpfr_set_emax, mpfr_set_emin, mpfr_clear_flags, GMP allocator hooks).
    • PCRE2 entries cover functions that Base regex code calls, by PCRE2 API manual. Match writes match data and JIT stack of match context.
    • BLAS and LAPACK entries come from \param role comments of Reference-LAPACK source: [out] written, [in] read, [in,out] both. Generator: gen/foreign/blas_lapack.jl; output: src/Effects/engine/foreign_blas_lapack.jl.
    • Symbols: every BLAS and LAPACK routine that LinearAlgebra calls. [in] argument that routine modifies and restores (A of ?ormrz) counts as written.
    • Hand entries cover CBLAS dot products and ?axpby, which Reference-LAPACK lacks. lbt_ configuration of libblastrampoline stays open.
    • BLAS entry applies only to call into libblastrampoline or OpenBLAS, by string or constant global. Same name in other library stays open.
    • No prefix rule: unknown mpfr_ or __gmp name stays open, because wrong entry gives false definite write. Call with fewer arguments than entry names stays open too: same name, other library.
    • CI lacks the headers and LAPACK source. Generators do not run there; committed files are the source of truth. Tests compare them with hand classification.
  3. Static call (one method matches, or Core.invoke with constant selector): callee summary. No method matches: call throws, so code after it is dead. Summary per variant: instance plus constant arguments callee uses as field name. getproperty(x, :a) keeps field a. Constant Bool argument that callee uses as branch condition also makes variant. Variant code drops blocks branch never reaches. Branch on === of two constants folds too: getproperty(::Task, :rngState0) variant drops :backtrace branch. Only variant constants fold; === adds no variant parameter. HAMT.path(trie, key, h, false) skips copy-on-write store, so ScopedValue read writes nothing. Julia inference resolves the same constant.
  4. Static call on callable holding object below caller parameter: callee stores and result apply now. Accesses go into callback record for caller.
  5. Run-time dispatch in package code with at most 3 matching methods: join their summaries. All agree: their certainty. Disagree: possible. Access that some members lack takes sources of open operands, as open dispatch does: operand types pick member. Blind access of one member and exact access of another disagree: join gives possible.
  6. Base interface function with documented contract (setindex! writes collection; length reads only; view result lies within array). Breach in package method is finding.
  7. Else open: possible write on operands; result may point into operands, one direction, and to unknown. TaskLocalRNG holds no object: operand that is or holds one gets open call possible default RNG write on unknown. Name states write whatever method runs. Base IO function (print, write, read) writes its IO stream operand: definite IO write. Stream is first operand; write(to, from::IO) also reads from. Value operand (show(io, other::IO)) takes open write only. Random draw (rand, shuffle!) writes its AbstractRNG first operand: definite RNG argument write. TaskLocalRNG operand holds no state: draw writes default RNG of current task (rand!(default_rng(), A::AbstractArray)).
  • Splat of tuple or array with unknown length: dispatch on Vararg of element type. Callee parameters past fixed operands take any element. Dims and other tuple type with free length parameter count as unknown length.
  • Splatted tuple slot has unknown position, so caller tuple collapses to deep. Splat of other collection stays open: its iterate runs.
  • Instance specializes on call argument types. Callable type known to caller is concrete in callee too, so step 3 reaches its method.
  • @invokelatest f(x) with constant GlobalRef resolves as call f(x), keywords included (Base.invokelatest_gr).
  • Constant binding has its value in analysis world. IR world range can start before binding exists: @invokelatest reads binding in latest world.
  • Callback record keeps write path short. Tuple foreach wraps closure in foldl reducers: closure writes lie three steps below reducer.
  • Caller maps record to its own objects. Callable still holding object below caller parameter passes record to next caller.
  • Root unit has no caller: its verdict resolves records left in its summary.
  • Access that only resolved records add carries callback mark: callable argument makes it (map(f, xs) runs f).
  • Record with fresh argument applies now: caller merges fresh objects of callee into one, so record would lose them.
  • Join resolves records of its members. Member disagreement on access gives possible.
  • Recursion repeats record on same targets: record applies once.
  • Callable of abstract type stays open (step 7): solve reached no dispatch for caller type.
  • Steps 5 and 6 assume methods loaded now. Write they find keeps certainty. "Writes nothing" from them is at most possible.
  • Contract: first and generic isempty start iteration of argument (isempty docstring warns). Type with own isempty or isdone method uses its summary.
  • Contract entry holds only behavior Base documents. Base type that writes where others read (iterate on Iterators.Stateful) gives possible write when operand type admits it.
  • Query (comparison, size, predicate, arithmetic) reads arguments. Its result is new value.
  • Alias query (convert, getproperty, keys, max, conj, adjoint) reads arguments. Its result may point beneath them.
  • Element query (getindex) result is element of collection or lies beneath it, never in indices.

  • Function with callable-first form (get, get!, merge!): contract holds only when first argument cannot be callable. Else call stays open.

  • Logger interface (AbstractLogger): shouldlog, min_enabled_level and catch_exceptions are queries.

  • Query result that may alias every argument tripled JSON effects time and changed no verdict.
  • Open call (step 7) whose open operands come from opaque and opt-out arguments only: no finding (Provenance). Opaque argument counts on coverage line: open dispatch on opaque data.
  • Other open call: doubt in code, possible finding.
  • Limit 3 is compiler max_methods, never below. Limit 8 reached 20 times more instances on Distances.
  • Library code joins nothing: its run-time dispatch stays open (step 7). Joins there raised possible share and cost most time.

Task bodies

Engine follows task body as call of body. Else @spawn, @async and @threads hide body effects.

  • Task(f) runs f() in new task when call on every later path starts task (schedule, yield, yieldto, enq_work).
  • @spawn, @async, and @task with schedule build and start task this way.
  • Other task may never run: Task(f) keeps old resolution. jl_new_task stays unresolved, so body effects are blind spots.
  • threading_run(fun, static) of @threads runs fun(thread) in tasks. Thread number takes no operand: constant would make variant.
  • Callable of abstract type, or callable stand-in, keeps old resolution: unresolved foreign call or dispatch.
  • Body stores and accesses apply at call. Callable holds caller objects, so no callback record waits for caller.
  • New body object stays in task when caller cannot reach it. Reach starts at body result and at stores into caller objects or globals.
  • Body store of new object into unknown object stays in task: task storage of new task, for one. Caller load from unknown object gives unknown object anyway.
  • Result is new task. Body result goes into result slot of task: fetch loads it.
  • New task owns its default RNG state and task-local storage. Body writes to them stay in task.
  • New task takes scope of caller: body ScopedValue reads stay.
  • New task derives its RNG from RNG of caller. Body draw before reseed reads default RNG of caller.
  • Derivation advances RNG state of caller (jl_rng_split): definite default RNG write, also for body that reseeds.
  • Write alone draws nothing: caller-chosen RNG (Effect kinds) counts calls that read default RNG.
  • Body that reseeds before every draw on every path passes hidden-input. Its other reads of task state drop.
  • Reseed: seed!(seed) or seed!(TaskLocalRNG(), seed), with seed that cannot be nothing.
  • seed!() takes system entropy: draws after it stay open.
  • Call reseeds when each callee variant reseeds before every normal exit. Helper reseed!(seed) counts.
  • Summary keeps seeds (every normal exit follows reseed) and draws (draw can come before reseed).
  • Must analysis on blocks: reseed holds at block start when it holds at end of every predecessor. Entry block starts without it.
  • Call cycle member starts reseeded; widen lowers fact. Shortcut unit never reseeds.
  • Draw: statement that reads default RNG. Callee draw before its own reseed counts.
  • Reseed in plain function keeps hidden-input: it changes RNG of caller. Only task body escapes.
  • Holds of task body stay in task: release balance skips task start.

Stand-in cuts

  • Cut: call or store statement live at declared signature and dead at stand-in signature. Engine never sees it, so unit summary carries cut.
  • Causes: call that fails on stand-in only, whose callee engine never sees; type test that stand-in decides (x isa BigFloat && (STATE[] += 1)).
  • inference stage finds cuts: units with dead call or store statements first, then declared-signature inference of those units only.
  • Failure check of units gives failing calls: model-type inference decides them. Throw helpers fail on every signature, so they are never cut.
  • Package call that fails on stand-in only gets no failure-check spot, but stays cut: stand-in can dispatch to other method.
  • Package units and library instances count both causes, with model-type check for library instances.
  • Base, Core and stand-in methods count failing calls only: Base keeps documented contracts, so its type branches keep same effects (findings.md, Confidence and blind spots).
  • Generated code differs per signature. Its statements match no statement of other signature, so generated method clears no cut.
  • Callers inherit cut. Method with cut is incomplete. Verdict none with cut goes to coverage line: stand-in cuts path.

Release balance

Summary keeps hold count per resource place at normal exit and at throw exit. Count is exact (acquires less releases), unknown, or blind.

  • Resources: lock, Semaphore slot, file that open returns. Resource place: one target of operand, exact caller place or fresh object.
  • Count key: resource place and resource kind. Fresh IOStream holds file and own lock: they count apart.
  • Merged fresh objects of callee count together: open result is one of them.
  • Operand with other targets: blind spot release pattern.
  • Primitive table: lock, unlock, trylock on lock; acquire, release on Semaphore; open with IOStream result; close on IOStream.
  • Table also: wait(::Condition) releases lock and takes it again.
  • Engine never reads lock, semaphore or wait bodies. It reads open and close bodies for their IO.
  • Base libuv lock (iolock_begin) holds no Julia object: engine skips it.
  • lock(f, l), open(f, path) and @lock l expr need no entry: each releases in finally, which dataflow balances.
  • trylock gives blind spot release pattern. Count that follows its result comes later.
  • Dataflow over CFG blocks. Statement that may throw (compiler nothrow off) inside try has edge to its catch block.
  • Block keeps at most 4 paths: counts and branch conditions taken. Fifth path joins all paths into one.
  • Branch on condition that path took before takes same side: l && lock(x) … l && unlock(x) balances (Base @_lock_ios).
  • Condition is forgotten when loop runs its statement again.
  • Primitive that throws: acquire takes nothing, release still counts. unlock throws only when lock is not held.
  • Join of different counts gives unknown; count that grows round a loop gives unknown.
  • Throw exit: statement that may throw outside every try. Its count joins into throw-exit count.
  • Call applies callee counts on caller places like writes: through join and callback record. Callee throw-exit count joins at call statement.
  • Normal-exit lock or semaphore count not 0 on argument or global: lock write. Exact count gives definite; unknown from join gives possible.
  • F98 (unguarded-release) fact: statement throws outside every try while method holds resource. Release is skipped.
  • Hold comes from own acquire or callee normal exit. Callee throw-exit count alone gives none: finding goes to method that acquires.

Solve and cache

  • Call graph over variants; strongly connected components from iterative Tarjan; solve bottom-up.
  • Components solve on all threads. Component starts once each component it calls has solved.
  • Component reads summaries of its members and of variants they reach alone, so thread schedule changes no summary.

  • Inside instance: rounds over IR until targets settle. These rounds apply callee stores only. One settled round then applies callee accesses.

Lifecycle

Array def-use per method: rows 10 and 11 of phase5.md.

effects stage finds array events per unit; it holds IR. lifecycle stage merges units and gives def-use per allocation. Rules read lifecycle facts only. Code lives in src/Effects/arrays.jl (events) and src/Lifecycle.jl (merge over units).

Allocations

Allocation: statement whose result is new array that unit code alone holds. Base table gives its kind:

Kind Calls
undef similar; Array, Vector, Matrix, BitArray constructor with undef operand
filled zeros, ones, fill, trues, falses
broadcast Base.materialize of broadcasted result: f.(x)
collected collect, comprehension (collect of Generator), map
slice getindex on array with range or Colon index operand: A[:, i], v[2:end]
copied copy, vcat, hcat
  • Package call result is no allocation: name trust tells nothing about whether result is new.
  • Result type: Array, BitArray, or array stand-in (similar and broadcast of stand-in keep it). Stand-in stands for caller array type.
  • Other result type (SVector, GPU array, OffsetArray) is no allocation: element and index rules differ.
  • Constant dimension operands give length. Else length is unknown.
  • Allocation in loop is new array each iteration. Its events count per iteration.

Identity

  • Allocation value: SSA value of allocation, and π node or typeassert of it.
  • View: alias-table result (effects.md, Roots) of allocation value. Events through view carry view; they never give coverage.
  • .= target over every element (a[:] .= x, a[1:end] .= x) is allocation value. Fill loop ranges below cover.
  • φ node that joins allocation value with other value ends identity: later uses are unknown events.
  • Loop φ that joins allocation before loop with allocation in loop body gives rebind pair (F41).

Events

Each statement that uses allocation value gives one event, with statement span, callee and operand position. Position counts positional operands only: kwcall keywords drop out. Event keeps Base function that call takes as first operand: vcat in reduce(vcat, a). ! call that takes array as written and source operand gives read, then write (map!(f, a, a)), or write, then escape when it stores array itself (fill!(a, a)). ! call that reads old elements of array it writes (sort!, reverse!, unique!, map!(f, a)) gives read, then write.

  • shape: size, length, axes, eachindex, firstindex, lastindex, ndims, eltype, isempty, similar, keys, LinearIndices, CartesianIndices, checkbounds, isassigned, sizeof, strides, stride, ===, isa, typeof, isdefined. Reads no element.
  • read: getindex reads elements at its index operands. first, last and only read one element. dotview with scalar index reads element as getindex.
  • Other non-! call reads whole array. So does non-written operand of library ! call: copyto!(b, a) reads a.
  • broadcasted result reads every element of its array operands when broadcast runs.
  • write: setindex! writes elements at its index operands.
  • Whole write: written operand of fill!, copyto! with two operands, map!, broadcast!, Base.materialize! (a .= …), rand!, randn!.
  • copyto! and map! write as many elements as shortest source. Whole only when each source has same extent: array itself, x in similar(x), or x in Vector{T}(undef, length(x)), and no ! call writes x. Else unknown.
  • Other ! call on written operand: unknown write. It can read first (sort!) or write part.
  • resize: written operand of resize table call (effects.md, F48 tables).
  • escape: return; stored operand of builtin store; closure capture; foreign call operand; pointer conversion; index operand of view (b[idx] .= 0), after whole read by bounds check outside @inbounds, or count of Boolean mask.
  • Other operand of ! call escapes when type of written operand can hold array (push!(c, a)).
  • Non-written operand of package ! call escapes: name promises one written operand, and call can write others. Distances colwise!(metric, r, a, b) writes r.
  • Operand after written operand with call method (functor) of library ! call escapes: map!(scale, r, x) writes r. Run of functors passes this on.
  • Operand of non-! call escapes when result type can hold array: tuple, constructor, abstract result.
  • Operand escapes when result type meets its type: call can return it (float(a), package pass(a) = a). Unary *(A) returns A.
  • Base copy, collect and reduction calls, Array constructors, and arithmetic with two or more operands, read operand whole. Result holds its elements, never operand itself, whatever result type: vcat of stand-in gives wrapper type.
  • copy, vcat, hcat and Array constructors can keep unset slots of reference elements unread: operand of such type escapes.
    • Concatenation of Array operands reads slots, as Julia 1.13 does: vcat with operand of two or more dimensions, hcat of vectors only, operand of three or more dimensions. hcat with matrix keeps slots. Unknown dimensions or array type: escape, so no false definite finding.
    • vcat of vectors reads slots that convert to promoted element type. Promotion can run package code (promote_rule), so Corset misses that read.
  • Type can hold array when element or field type meets array type, at most 3 steps deep. Base storage (Array, Dict, Set) holds elements only; view or wrapper also holds fields (SubArray parent).
  • Index operand keeps constant value. Non-constant index keeps nothing.

Paths

  • sure: event runs once on every path from allocation that returns. Path that throws counts as none: guard keeps read sure.
  • Event block post-dominates allocation block over blocks that reach return, and both blocks share loop nest.
  • branch: allocation run can skip event. loop: event lies in loop that allocation lies outside.
  • Order: block order of sure events follows dominance. Statements in one block keep IR order.
  • Fill loop is one sure whole write at loop exit when every condition holds:
    • Loop iterates eachindex, LinearIndices or CartesianIndices of a, or of x in a = similar(x) when no ! call writes x.
    • Or loop iterates axes(a, 1) of vector, 1:length(a) or 1:lastindex(a) of Array, or 1:n and Base.OneTo(n) for n in zeros(n).
    • Body writes a[i] with iteration value i, in block that runs on every iteration.
    • Loop exits only through its header, and its exit block post-dominates allocation block.
  • Other loop write is loop write with unknown coverage.

Rebind

Rebind pair: loop header φ joins allocation before loop with broadcast in loop body. .= keeps behavior when each holds:

  • same_axes: every array operand of broadcast is φ value; scalars may join.
  • same_type: allocation and broadcast have one concrete type.
  • exclusive: loop alone sees both arrays:
    • Each loop that holds header also holds allocation, but header loop: one allocation per loop entry.
    • Loop reaches no use of allocation but header φ and loop exit φ that joins only pair arrays.
    • Use of allocation before loop is no view, lazy broadcast or escape; return is allowed.
    • φ value: use in loop dominates broadcast, or is its operand. Use after loop needs no loop exit after broadcast.
    • Broadcast value: use in loop is no view, join or escape but return.

Facts

  • Per package method: ArrayLife per allocation: site span, source statement, kind, constant dimensions, events in order, rebind pair.
  • Units of method merge by allocation span and source statement: mapping can give two allocations one span. Array of generated method is lifecycle blind spot: its units lower other code. Events merge by all fields but path; path of merged event is worst over units.
  • Event that one unit lacks is branch at best: that unit skips it.
  • Dimensions and rebind pair stay only when all units agree. Each rebind condition holds only when it holds in each unit.
  • Definite verdict reads sure events only. branch, loop or view event that can change verdict gives possible.

Rules

  • temporary-array (F32): broadcast or collected allocation whose only events are shape reads and one sure read by consuming-table call. Fix likely (generator sums in order): sum(f.(x)) → sum(f, x) for reduction that takes function; comprehension → generator; sum(collect(it)) → sum(it). Other forms manual. Fix edits reduction argument at operand position of read: comprehension span is line only. reduce(vcat, A) and reduce(hcat, A) are exempt: Base concatenates in one allocation.

  • unwritten-element (F34): filled allocation with constant length. sure element writes cover part of it; then whole read. Kind placeholder. Always possible: fill value can be data (e = zeros(n); e[1] = 1.0). Fix manual.
  • constant-array (F39): filled allocation without write, resize, escape or join. Fix likely: swap call for FillArrays.jl Fill, Zeros, Ones, Trues or Falses, and import it above module code.   • broadcast-rebind (F41): rebind pair with same_axes, same_type and exclusive. Fix likely: x = f.(x) → x .= f.(x). Package call that keeps array but returns no array hides alias. Right side of other assignment: manual.

Process model

  • One process per run. Corset loads target into its own process, as Aqua.jl and JET do, so later stages read compiler state directly.
  • Fresh process only: no Corset.check() inside runtests.jl. Test code would change method table, and --code-coverage changes optimized IR, so findings would depend on what ran before.
  • Command line always builds temporary environment: nameless project that develops target by path, starts from target Manifest, and adds test dependencies and Corset by path. Every target version stays when Corset accepts it. Otherwise packages Corset shares with target move, fewest first: Corset direct dependencies, then its dependency closure. Build prints each move; coverage line counts each loaded package at other version than Manifest pins as blind spot. Target compat that blocks every move fails loud (exit 2). Cache environment by hash of Manifest, Project.toml, Julia version and Project.toml of each path package. Path packages: Manifest entries, Corset, test sources, and [sources] of each path package in turn. Key names no directory. Each run copies cached environment into new temporary directory. Copy points Manifest path entries at directories of this run, by uuid. Copy drops [sources]: Base loading reads Manifest only, and [sources] names root, which keys analysis apart. Copy of project elsewhere reuses environment and analysis. Build holds file lock. Next run removes lock of dead process at once when lock is older than 30 s. Crashed build blocks no later run.
  • Relaunch Julia with JULIA_LOAD_PATH set to that environment and @stdlib only, so default environment (@v#.#) adds no package, trigger or method.
  • Relaunched process runs with coverage and allocation tracking off, whatever flags relaunching process has.
  • Target loads after Corset, so its methods must invalidate no Corset code. Keep inferred types concrete; put inference barrier on dependency callee that infers abstract types. test/invalidation.jl checks.
  • Package stage loads in place only there and in Corset tests: Base.locate_package must give target entry file by real path. Other path is internal error: findings would describe other code.
  • Load each extension's trigger packages: extension activates only when all triggers are loaded.
  • Cache check runs before package load: unchanged rerun loads nothing.
  • Native abort kills relaunched process, and Julia try cannot catch it: LLVM UNREACHABLE in Enzyme generator that inference runs on stand-in types.
  • Relaunched process runs on thread counts of relaunching process. inference stage infers each worklist wave on all threads, then merges results in queue order: findings and output order match one-thread run. Wave threads also infer model and declared signatures that calls which never return need (call_verdicts!), once per unit. Effects engine solves call graph components on all threads (engine.md, Solve and cache). Wave is queue head of WAVE signatures per thread, since wave keeps each compiler frame until its merge.
  • Relaunched process keeps crash journal: store key of each method and signature before its inference, store entry after it. Inference writes stderr to crash log.
  • Start record tells whether inference ran alone. Crash beside other inferences makes next run infer each inference in flight alone, so next crash names one method.
  • Journal open cuts torn last record: abort on one thread can stop write of other thread.
  • Offset inference of index proof (types.md) writes records too, with own key prefix and no entry.
  • Relaunching process supervises: relaunched process that dies by signal, with key in journal that has no entry, runs again. It prints one note per crash with log path.
  • Next run reads journal: entries serve as method store, so finished work stays done; crashed key gets no inference and becomes blind spot inference crashed process.
  • Run ends with internal error after 32 crashes. Julia exception never reruns: it stays internal error.

  • Each footgun: positive case, negative case, fix case. Manual fix has no edits: positive snapshot shows its text.

Rule contract

Main goal of rewrite: clean structure. Legacy implemented each rule on its own, so analyses repeated and code grew.

  • Each stage computes facts once per run: syntax index, array def-use, scopes, module facts, typed IR, effect facts.
  • Rule is one pure function: facts in, findings out. Rule code imports only facts API; test enforces it.
  • Rule that needs new information adds fact to its analysis. Long rule signals missing fact.
  • Registry is data: name, group, footguns, stage, fix tier. Docs page per rule comes from footgun table.

Package load

Loading runs code. Stages after package load (package, inference, effects, lifecycle, external) run only on package with name; Julia apps qualify. Scripts and nameless environments get syntax and scope. Extensions are analyzed with test dependencies installed and their triggers loaded; untested-extension reports trigger missing from them. Later: definitions-only load for scripts.

Engine loads package only when enabled rule needs stage after syntax. Load that throws becomes load-error finding (findings.md).

package facts hold live objects (Module, Method, DataType); findings stay plain data. Package code: methods and types whose module is package module (root, submodules, extensions) and whose file lies under package root. Code that other packages' macros write elsewhere is not package code.

Method span: package stage pairs each method with definition node at its file and line. Exact span when one definition node of that name starts there; line precision otherwise (@eval loops, macro output).

UI cases for rules after syntax: case directory holds package (Project.toml with name and uuid, src/). Harness loads it in test process under unique name. Fixture that extends function it does not own (piracy) adds only methods no other case calls, so later cases see same dispatch.

Incremental runs and disk cache

  • Disk cache (Cache) holds one entry per analysis key: key line, then serialized analysis. Analysis holds leveled diagnostics, baseline keys, check problems, blind spots and analyzed files. Settings and baseline apply each run.
  • Key: SHA-256 of Julia version, Base.CacheFlags, checked path, serialized flags, each load path environment with Manifest and preferences, Corset project file and source, analyzed files, and every file of project root and Manifest path entries but Corset root. Corset root can hold depot and outputs beside its code.
  • Key reads file content, so fresh CI checkout hits. Names that start with dot and cache directory stay out of key. Corset source counts by its Julia files.
  • Key names paths relative to anchors: project root, and project, Manifest and preference files of each load path environment. Other files keep real path: entry relocates root alone. Load path Manifests count by entries, path entries as anchored real paths; other files count by bytes. Copy of project in other directory gives same key.
  • Root anchors only when no key file but Manifest holds root path text. Code that names own root can act on it, so key then names root.
  • Entry of anchored root stores root as mark in every string; read puts root of checked copy in its place. Root left outside strings, such as in Symbol, fails store. SubString fails too: its offsets would go stale.
  • Blind spot: code can derive behavior from own location by other means, such as path length, or read files outside root by relative path. Key holds neither.
  • Cache keeps newest entries within byte budget (Cache.ENTRY_BYTES); hit makes entry new.
  • Location: Corset scratch space analyses in Julia depot. CI that saves depot keeps cache. --no-cache turns cache off.
  • Relaunching process computes key of relaunched process (temporary environment, load path @:@stdlib) and asks cache first. Hit loads no package and starts no process. fix always relaunches.
  • Run that analyzes without method store of checked path prints one note: first analysis can be slow; later runs reuse cache.
  • Later: syntax stage findings per file, keyed by file content hash.
  • inference stage keeps method store per checked path beside analysis entry. Store holds one entry per inferred method and signature: reached signatures, stage facts and blind spots.
  • effects run adds effects record of unit to each entry (effects.md, Units and IR).
  • Entry holds plain data: spans, names, call signatures. Typed code stays inside stage, so no rule reads data that store leaves out.
  • Entry depends on content hash of file of its method, since spans hold byte offsets.
  • Entry also depends on lowered code of each package method that inference read through compiler edges, transitively. Lowered code holds macro output and @eval code.
  • Code digest also holds each package binding that lowered code reads: global reference, Sub.C, getglobal(Sub, :C). Inference folds their values.
  • Package module that flows elsewhere (slot, argument, constant container) counts whole: every binding of it and its submodules.
  • Binding counts by value when plain constant (number, string, symbol, immutable struct of those), by name when function or module, else by type.
  • Closure that edit renumbers has other code, so lowered code also checks what closure and keyword body names mean.
  • Edge walk passes through dependency method whose specialization names package type or function: map(f, xs) with package f depends on f.
  • Entry also depends on meaning of each package name it read. Callee name (call M.f, new M.T) means ids of its package methods. Type name (type M.T) means layout.
  • Entry reads callee of each call its code makes and of each walked instance; reads package types of signatures and their field types.
  • So new method of package function drops only entries that call it. Edge of call without match names no method; callee name covers it.
  • Entry records generated code of each @generated instance it read. Run calls generator again and compares.
  • Store keeps no entry whose generated instance names closure or keyword body type: edit can remove that name, and then store cannot read type back.
  • Store key line hashes environment, Corset producer source (engine.md, Solve and cache), analyzed file list and package shape. Other key drops whole store.
  • Producer source counts by content even when Corset checks itself: analyzed file list counts files by path only.
  • Environment counts by load path position and content. Relaunch copies environment to new directory each run, so copy keeps key.
  • Package shape: text of files that hold pirate methods, and id of each method on callee of other module (Base.show(::IO, ::T)). Non-analyzed files in src, ext and deps count too.
  • Base code reaches pirate and foreign methods with no edge to package code, so their change drops whole store.
  • Type counts by layout: field names and types. Struct that edit redefines serializes as before.
  • Limit: callee code call that matches too many methods leaves no edge. New package method under such call can leave entry result wider than fresh one.
  • Limit: module that code computes (parentmodule(f)) counts by name only.
  • Run checks each entry against file hash, names, lowered code and generated code; infers only invalid ones; writes store with entries this run used.
  • Result stays serialized until entry proves valid: it can name closure type that edit removed.
  • Edit of one method invalidates entries of its file and entries that read its code.
  • Later, engine runs on Salsa.jl (julia-vscode, MIT; JuliaWorkspaces.jl uses it): inputs are file texts and Project.toml; derived queries are parse trees, facts and findings. Edit recomputes only dependents; early cutoff stops at unchanged facts. Salsa keeps tables in memory only; disk cache starts new process warm.
  • Inference runs inside compiler, outside Salsa tracking: typed dependencies come from compiler edges between methods.
  • Later: warm daemon keeps Salsa tables and loaded package, so edit costs only its dependents.

7 Alias rules

Rules read per-unit statement events and must-alias pairs.

  • iteration-mutation (F48): collection written inside loop that iterates it. View result counts: keys(d) iterates d.
    • Loop: IR blocks on cycle through iterate(x, state). Collection: operand x.
    • Write: ! call or field store whose written operand is collection, or holds place at or above collection place.
    • Same object: written operand and x share IR value after view calls, or both are one place without fresh path.
    • Size change on same object (push!, delete!, empty!, …: RESIZE_FUNCTIONS) gives definite; other write possible.
    • Element write below collection never counts: for b in boxes; b.n = 0; end.
    • Overlap through Deep place: blind spot loop write place unknown. Name tier cannot tell objects below one root apart.
    • setindex! on array replaces element: no finding. On dictionary, key can be new: possible.
    • Deletion from Dict, IdDict, WeakKeyDict, Set, IdSet, BitSet: no finding. Base deletes from each while iterating it.
    • Base filter!(f, ::AbstractDict) warns: "dictionary types may not support mutation during iteration". Other types count.
    • Consuming call with closure (foreach(x -> push!(v, x), v)) stays unseen: its loop is in library code.
    • Fix manual: iterate copy (collect(keys(d))), or collect changes and apply after loop.
  • self-alias (F50): ! call writes operand while it reads same memory through other operand.
    • Same object: written operand and other operand are one IR value after π nodes, or one place (F48 same object).
    • Shared memory: operands share IR value only after view calls (view, reshape, …): overlap depends on index values.
    • ALIAS_BREAKS: functions that give wrong result, or throw, on one object as output and input.
    • Docstring forbids it (mul!, transpose!, adjoint!); output starts from init value (sum!, prod!, any!, all!, count!).
    • Base throws (circshift!, circcopy!); splice! reads slots its resize freed.
    • Entry names input operand that breaks: splice! breaks on replacement only, never on index operand.
    • Warned function: matched method docstring carries Base aliasing warning (Base._DOCS_ALIASING_WARNING), or ALIAS_BREAKS function.
    • Same object to ALIAS_BREAKS function gives definite. Shared memory to warned function gives possible.
    • Same object to other warned function: no finding. Base docstring calls map!(f, A, A) equivalent of map!(f, A).
    • Exempt: functions that unalias operands with Base.unalias (copyto!, copy!, setindex!, prepend!, broadcast!, materialize!).
    • Fix manual: pass copy of read operand, or write into other container.
  • stateful-reuse (F51): method restarts iterator whose type admits stateful iterator, or lets it escape after start.
    • Start: iterate without state, contract start (first, generic isempty) or consuming-table call.
    • Restart: second start of same object on one path. Loop re-entry counts; zip(itr, itr) starts itr twice where code consumes or returns it.
    • Value that loop body defines is new object on each pass: path through its definition makes no pair.
    • Load of unchanged container and key (groups[1] in loop) can give same iterator again: possible.
    • Escape after start, or start after escape: return, store into object or global, operand of package call.
    • Escape counts for tuple, new or constructor result that holds iterator: (head, itr) lets itr escape.
    • Generic isempty starts only when isdone gives missing. EachLine and Stateful define isdone.
    • Other isempty methods that can match argument type give possible start.
    • Inferred result of isdone decides, package method included: Missing gives definite start, union with it possible.
    • Parameter started once without escape: no finding.
    • Multi-pass types: AbstractArray, AbstractDict, AbstractSet, AbstractString, Tuple, NamedTuple, Pair, Number, AbstractChar.
    • Type counts when it can hold both kinds: abstract type outside multi-pass types, or union of both kinds.
    • Concrete type and exception-table stateful type are one kind. Restart there is deliberate: first(eachline(io)).
    • Struct family (Bag{T} where T) is one kind, unless field has open parameter type (inner::T): iteration can pass to field.
    • Parameter inside field type (items::Vector{T}), or parameter bounded by such family: iterate body decides kind. Pair with its start is blind spot.
    • Consuming call that only specialized method serves (minimum of distribution): method body decides start. Pair with it is blind spot.
    • Generic method and package method for other type both serve call: start is possible. Base methods keep iteration contract; multi-pass types restart harmlessly.
    • Argument that admits Iterators.Stateful reaches generic method with it: package method that cannot take it keeps definite.
    • Definite when starts and escape are in method code and objects must-alias; on in default preset. May-alias gives possible.
    • Fix manual: Iterators.peel, thread iterate state, or narrow argument to multi-pass type.
