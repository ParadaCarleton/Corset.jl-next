Corset Rewrite Plan

Rule set, shared analyses and decisions for rewrite of Corset. Each analysis runs once per run. Each rule is small query on analysis output.

37 rules on main kept or changed 5 rules removed 18 rules in open work under review 40 rules proposed 8 analysis families

Principles

  • Compute each expensive step once per run. Share output with every rule.
  • Group rules by analysis they read. User-facing group is metadata only.
  • Give each finding confidence: proven or unproven. One setting filters them.
  • Map every finding back to source bytes. Fixers edit lossless syntax tree.
  • Keep linter process warm. Load target package once. Infer only methods that hold candidate sites.
  • Use JET in tests as oracle for runtime-dispatch. Read typed IR from native compiler at lint time (proposal).

Groups and strictness

Four groups replace default and pedantic: correctness performance composability readability. Readability holds house style: anything that makes code hard to read. Composability holds code that must work with other types and future Julia versions.

Noise is no longer reason for group. Each finding says how sure analysis is. One setting picks what to report:

finding
strictness = "proven" (default)
strictness = "unproven"

Rules with both kinds today, unlabeled: unmarked-mutation and float-widening ("may write", "may widen" past candidate budget); nan-initializer and constant-array (sites fixer skips).

! convention

! marks every function that can change state outside itself, IO excepted. When behavior is inconsistent, ! names functions where bug can be.

Does method write memory caller can see?infer_effects: inaccessiblememonly false
no → no !
yes ↓
Is every written object IO?stdout, files, logging, abstract io::IO argument
yes → no !
no ↓
Is only write advance of RNG?task-local or global generator
yes → no !
no ↓
Is only write cache with cheap proof?known memo macro, or one owner method and non-public binding
yes → no !
no ↓
Writes argument, global, or result that aliases global state
require !
  • Known memo forms: @memoize (Memoize.jl, Memoization.jl), @cached (Caching.jl), get! on LRUCache.jl LRU.
  • Other caches need # lint: comment with reason. Do not invest in deep invisibility proofs.
  • Effect summary records whether method result aliases global state. Write through such result counts as global write, so caller needs !.
  • Requirement propagates: caller of ! function on global state needs ! too.
  • Full ownership (borrow) checking is deferred. Revisit for concurrency rules.

Decisions

decided

Groups

correctness, performance, composability, readability. pedantic removed.

decided

! scope

Argument and global writes. IO and RNG exempt. Memo caches exempt with cheap proof only.

decided

Annotations

::Any is explicit opt-out. Abstract argument types are intended.

decided

constant-array

Keep. It prevents pointless allocations.

decided

Borrow checking

Defer. Revisit for concurrency rules.

open

Strictness wording

Setting names "proven" and "unproven" are draft. Confirm meaning: report proven problems only, or also unproven safety.

open

one-letter exemptions

i allowed. Decide j, k for nested loops, and T for type parameters. Prefer role names (left, right) over num1, num2.

open

specialization-blowup

Replace overspecialized-anon-fun with measured specialization count?

open

concrete-return

State what it must catch, or remove it.

decided

Rule names

Follow main: unstable-variable, unstable-return, *-anon-fun.

decided

float64 in #113

Drop float64 sub-check from type-disruption.

decided

Union width

One limit for unstable-variable, unstable-return, abstract-field: at most one member besides Nothing and Missing.

decided

Public struct fields

concrete-annotation accepts only type parameter (x::T) as fix, so abstract-field never reports result.

decided

Explicit Any

::Any, Vector{Any}, Any[] are approved opt-outs everywhere. abstract-element must exempt them.

conflict

literal-array and similar-array

Both push concrete array constructors toward similar. Keep one.

conflict

Annotation rules overlap

concrete-annotation covers invariant parameters (invariant-parameter) and results (concrete-return). Merge into one rule with sub-checks?

conflict

Union suggestion chain

enumerated-union message names AbstractFloat; abstract-float reports it. Proposal: message runs abstract-float exemption check and names Real unless method calls float-specific functions. No fixer collides: #116 maps Float64 to Real.

conflict

Name bans

banned-name and forbidden-pattern both ban text by config. Merge configs?

open

JET
