Corset Rewrite Plan

Footguns, checks, shared analyses and decisions for rewrite of Corset. Each analysis runs once per run. Each check is small query on analysis output. Old rule names live in rules-rewrite-history.md.

83 footguns 75 checks 8 analysis families

Principles

  • Compute each expensive step once per run. Share output with every rule.
  • Footguns are source of truth. Checks group footguns by analysis they read. User-facing group is metadata only.
  • Give each finding confidence: proven or unproven. One setting filters them.
  • Map every finding back to source bytes. Fixers edit lossless syntax tree.
  • Keep linter process warm. Load target package once. Infer only methods that hold candidate sites.
  • Read typed IR from native compiler at lint time. JET serves only as test oracle (proposal).

Groups and strictness

Four groups replace default and pedantic: correctness performance composability readability. Readability holds house style: anything that makes code hard to read. Composability holds code that must work with other types and future Julia versions.

Noise is no longer reason for group. Each finding says how sure analysis is. One setting picks what to report:

Checks with both kinds: missing-bang (dispatch past candidate budget may write), type-disruption (type branch), unwritten-element and constant-array (sites fixer cannot prove).

  • Known memo forms: @memoize (Memoize.jl, Memoization.jl), @cached (Caching.jl), get! on LRUCache.jl LRU.
  • Other caches need # lint: comment with reason. Do not invest in deep invisibility proofs.
  • Effect summary records whether method result aliases global state. Write through such result counts as global write, so caller needs !.

  • Full ownership (borrow) checking is deferred. Revisit for concurrency rules.

Decisions

proposal

Fix tiers

Each fix declares tier; setting picks highest tier applied. safe: behavior unchanged. likely: types or dispatch may change. breaking: API changes; ratchet absorbs new findings.

proposal

Project kind

Preset over groups and fix tier. library: all groups, likely fixes. application: correctness and performance, breaking fixes (no downstream). Infer application when Project.toml has no name; else require setting.

decided

No tests

Corset never reads or runs package tests. Signatures come from annotations: marker types for generic arguments, declared type otherwise. ::Any arguments infer as Any.

decided

Groups

correctness, performance, composability, readability. One group per check.

decided

! scope

Argument and global writes. IO and RNG exempt. Memo caches exempt with cheap proof only.

decided

Annotations

::Any is explicit opt-out. Abstract argument types are intended. result-conversion reports result annotation that converts, so annotations act as checks.

decided

Explicit Any

::Any, Vector{Any}, Any[] are approved opt-outs everywhere. untyped-empty and vague-type exempt them.

decided

Union policy (vague-type)

One policy for inferred locals, results and struct fields; argument annotations exempt. Nothing and Missing are free. Members from one module other than Base or Core form variant group. Allow at most one member outside that group.

  • Pass: Union{Circle, Square}, Union{DepA.Leaf, DepA.Node}, Union{Float64, ParseError}.
  • Report: Union{Int, Float64}, Union{String, Symbol}.
  • Report where union is created: merge in package method, or package declaration.
  • Union forwarded unchanged from dependency passes; strictness = "unproven" reports it.
  • Message suggests sum-type package (Moshi.jl, SumTypes.jl).
  • Baseline keeps existing findings from failing CI.
decided

Struct field fix

Fix for vague or concrete struct field is type parameter (x::T) only, so vague-type and narrow-signature fixes agree.

decided

Suggested abstract type

Always suggest Real for floats. vague-type and narrow-signature share one helper: float_to_real(typejoin(members)). Property test: applying any fix never creates new finding. Build general mechanism only if test keeps finding conflicts.

decided

Hard-coded arrays

type-disruption reports hard-coded Vector/Matrix/Array construction everywhere, zeros, ones, fill included. With template array: autofix to similar(template, T, dims). Without template: message teaches caller-supplied template or array type; autofix adds parameter in breaking tier. One shared initializer fixer serves type-disruption, constant-array and unwritten-element.

decided

type-disruption engine

Principle: values from outside inputs are weak. Literals, constants and globals must not change result type. Inputs combine by normal promotion. Same rule as NumPy 2 for Python scalars.

KindInputs combine asLiteral or constantExample finding
Numbersnormal promotion; Int32 with Int64 gives Int64 (pass)weak: must not widenx::Int32 * 2 gives Int64
Arrayskeep container kind; element types promotefresh Array must not take over containerx::JLArray .+ zeros(n) gives Array
Strings (later)String is correct common typeliteral is String alreadyrare; Julia already does this
Dicts, sets (later)keep container kind; key and value types promoteas for arraysrare
  • Marker types: one per kind. Numbers use 𝒯 <: Real; arrays use marker array type. Each marker is ordinary well-behaved type with normal promotion (promote_rule(𝒯, Int) = 𝒯). Base code runs on it unchanged.
  • Inference: infer each package method with markers in place of generic arguments (::Real, T <: Real, AbstractArray{T}). Use native inference and its cache. No JET, no Cthulhu, no custom interpreter.
  • Scan (family D, package methods only):
    • Arithmetic or promotion call mixes marker with foreign number type (x * 2, x + 0.5): report, even when result is still marker.
    • Value derived from inputs ends with type other than marker: report.
    • Branch on type (x isa Float64, T === Float32): report as unproven.
  • Why marker: Base has fast paths for Float32 and Float64. Real float probe takes them; marker takes only generic path, same as user number type.
  • Base: assume Base callees preserve types; analysis is sound only modulo Base. Optional concrete probes (Int32, Float32) catch Base-caused widening such as middle(::Int32) → Float64. Collect real Base widening bugs for upstream report.
  • Scope: version 1 covers numbers and arrays (F5, F6, F16). Strings and dicts need only new marker and result rule; engine stays same. Interfaces.jl can declare each kind's contract.
  • Cost (rough estimate, unbuilt): number marker 100–200 lines (promotion, conversion, arithmetic, comparison, one/zero, float, math functions); expect to add methods until inference runs clean on real packages. Mixing check 100–200 lines. Source mapping through TypedSyntax.jl.
  • No tests: markers come from annotations. ::Any arguments infer as Any. Unannotated methods are skipped; annotation reports them.
  • Syntax check stays for hard-coded Array without template. Shared fix helper finds in-scope type source (T, eltype(x), template array).
decided

Specialization count

specialization-blowup predicts from source: C finds methods that specialize on Function or Type argument; A counts distinct closures or types passed at package call sites. Compiled-instance count from precompile workload: later, opt-in.

decided

Borrow checking

Defer. Revisit for concurrency rules.

open

Strictness wording

Setting names "proven" and "unproven" are draft. Confirm meaning: report proven problems only, or also unproven safety.

open

one-letter exemptions

i allowed. Decide j, k for nested loops, and T for type parameters. Prefer role names (left, right) over num1, num2.

open
